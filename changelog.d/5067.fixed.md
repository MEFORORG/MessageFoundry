- **`provision-admin` and `admin-reset-totp` would now say only what a refused store open left
  behind.** For a server store whose schema falls short of this build's, both said "nothing was
  written". The open rolls its schema batch back and writes no marker, but on SQL Server under
  `[store].schema_management = auto` it may already have switched the database's
  READ_COMMITTED_SNAPSHOT and ALLOW_SNAPSHOT_ISOLATION options on, before that batch. That refusal
  now says so. When the write's own open refuses `provision-admin` for its key, cipher, store hop
  or schema after the authenticator key was shown, or one of its keyless checks does, it also says
  to delete the entry the operator may have added, as `admin-reset-totp` already did; at least a
  driver or connection failure of that open does not say so. It names the OS user for the audit
  row before it shows the key, not after. `provision-admin` now prints its key, cipher, hop and
  schema refusals through the same codec-safe rendering as the other store commands.
