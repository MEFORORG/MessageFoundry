- **A cluster convergence reload's audit rows name the reload and the operator act behind it.** Its
  `config_reload` row is built from the reload's own result, so a flag toggle or operator reload
  that lands before the write no longer puts that graph under the convergence actor; the row is
  marked `superseded` instead. Every reload row on a cluster carries `config_version`, the shared
  version it applied, so a follower's row names the operator reload it followed. A convergence
  reload that fails writes one `config_reload_failed` row per version, where it wrote none. A
  start's `config_loaded` row keeps its `loosenings` when a reload supersedes it, and a start that
  could not take its config snapshot still compares the digest its load took, so a changed config
  still raises `config_changed`; that row no longer writes a `null` shard. The
  `ClusterCoordinator` protocol now states that `config_version()` must answer before `start()`.
  (`vault BACKLOG #3076`, `vault BACKLOG #3109`)
