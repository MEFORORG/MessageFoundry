- **Channel scope is now structural on the management API, not a pattern each route repeats.** The
  store reads that take `allowed_channels` now require it, so a new caller that leaves it out fails
  type-checking instead of reading every channel. Engine-internal callers pass `None` by name, and a
  test refuses a literal `None` in the API package. Every by-id message route now opens the message
  through one helper that checks the caller's channel, audits a refusal and answers the same 404 as
  before, and a test fails if any other API module calls the store's `get_message`. A new test
  classifies every route of the default JSON API for channel scope, so a route nobody classified
  fails the run, and it runs the scoped GETs that take no path parameter with a scoped caller and
  an all-channels control. Responses, status codes and audit rows are unchanged.
