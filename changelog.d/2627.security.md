- **Channel scope is now structural on the management API, not a pattern each route repeats.** The
  store reads that take `allowed_channels` now require it. A caller that leaves it out fails
  type-checking instead of reading every channel. Engine-internal callers pass `None` by name, and
  a test refuses a literal `None` on those reads under `messagefoundry/api/`. Every by-id message
  route now opens the message through one helper. It checks the caller's channel, audits a refusal
  and answers the same 404 as before. A test fails if any other API module touches the store's
  `get_message`. Another test classifies every route of the default JSON API for channel scope, so
  an unclassified route fails the run. It runs the scoped GETs that take no path parameter as a
  scoped caller and as an all-channels caller. Responses, status codes and audit rows are unchanged.
