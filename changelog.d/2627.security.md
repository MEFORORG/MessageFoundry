- **Channel scope is now structural on the management API, not a pattern each route repeats.** The
  store reads that take `allowed_channels` now require it, so a new caller that forgets the scope
  fails type-checking instead of reading every channel; engine-internal callers pass `None` by name.
  Every by-id message route now opens the message through one helper that checks the caller's
  channel, audits a refusal and answers the same 404 as before, and a test fails if any other API
  module reads a message by id itself. A new test classifies every route of the API for channel
  scope, so a route nobody classified fails the run, and it executes each scoped list read with a
  scoped caller and an all-channels control. Responses, status codes and audit rows are unchanged.
