- **An LDAP search that does not end with success is an outage, never "no such account".** Each
  search the engine sends refuses any result code but success, with or without entries. That
  includes busy, unavailable, unwillingToPerform and adminLimitExceeded. It includes a time or size
  limit, and noSuchObject on a missing search base. Before, such a search read as no entries. The
  session reconciler would then have struck a present account toward revocation. A busy nested
  group search read as fewer groups. The reconciler now reads these as unavailable, which never
  revokes. A sign-in writes `auth.login_error` naming the code, and `check-privileges` names the
  code for the bind-account read. These refusals name the operation and the code, never the
  directory's diagnostic message. Other directory errors keep the text they had.
  **Not covered:** ldap3 fetches a ranged `memberOf` with follow-up searches of its own, and those
  are not refused.
  **The cost:** a code that recurs on every pass, such as a deleted search base, stops revocation
  and the role re-diff for as long as it lasts. It warns once per process for each operation and
  code, and latches no alert.
  **The nested group search is paged**, at 500 entries per page. So an account in more groups than
  a directory's unpaged cap no longer fails sign-in with sizeLimitExceeded. AD's cap, MaxPageSize,
  is 1000 by default. A page that does not end with success refuses the whole search. So does a
  later page that drops the paging control, and a search still paging after 20 pages. The pages
  already read are never used as the whole answer. A refused paged search is abandoned (RFC 2696)
  once the directory has sent a cookie, at the cost of one more round trip. Paging was measured
  against a loopback server through ldap3, not against a domain controller.
  **A response ldap3 cannot decode is an outage, not an unhandled error.** ldap3's default decoder
  raises `KeyError`, `TypeError`, `IndexError`, `AttributeError` or `UnicodeError` on a malformed
  response. Cases include at least a bind response carrying a referral, a result code outside its
  table, a malformed paged results control, and a Who am I value that is not text. A sign-in that
  met one would have failed with an unhandled error and no audit row. The searches, binds and
  Who am I read the engine sends now run inside one boundary. It maps such a fault to an outage when
  ldap3 raised it reading the response, and lets any other exception propagate. Such a fault now
  reaches the session reconciler as an outage, which it logs at debug level, rather than as an
  unexpected error, which it logged at WARNING for each account. After one, the engine closes the
  socket of a service-account bind that met it. (vault `BACKLOG #3010`)
