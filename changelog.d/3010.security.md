- **A directory search that does not end with success is an outage, never "no such account".**
  Every LDAP search refuses any result code but success, with or without entries: busy,
  unavailable, unwillingToPerform, adminLimitExceeded, a time or size limit, and noSuchObject on
  a missing search base. Before, such a search read as no entries, so the session reconciler would
  have struck a present account toward revocation, and a busy nested group search read as fewer
  groups. The reconciler reads these as unavailable, which never revokes, and a sign-in writes
  `auth.login_error` naming the code. `check-privileges` names the code for the bind-account read.
  The text of these refusals names the operation, the code and ldap3's name for it, never the
  directory's diagnostic message; other directory errors keep the text they had.
  **The cost:** a code that recurs on every pass, such as a deleted search base, stops revocation
  and the role re-diff for as long as it lasts, with one WARNING per code per process and no
  latched alert.
  **The nested group search is paged** (the simple paged results control, 500 per page), so an
  account in more groups than a directory's unpaged cap (AD's MaxPageSize, 1000 by default) does
  not end it with sizeLimitExceeded and fail sign-in. A page that does not end with success refuses
  the whole search, and so does a later page that drops the paging control, or a search still
  paging after 20 pages; the pages already read are never used as the whole answer. A refused paged
  search is abandoned (RFC 2696) once the directory has sent a cookie. Paging was measured against
  a loopback server through ldap3, not against a domain controller.
  **A response ldap3 cannot decode is an outage, not an unhandled error.** ldap3's default decoder
  raises `KeyError`, `TypeError`, `IndexError` or `AttributeError` on at least a bind response
  carrying a referral, a result code outside its table, and a malformed paged results control. A
  sign-in that met one would have failed with an unhandled error and no audit row. Each search,
  bind and Who am I read now runs inside one boundary that maps such a fault to an outage when ldap3
  raised it while reading the response, and lets any other exception propagate. The service
  account's socket is closed when its bind cannot be decoded. (vault `BACKLOG #3010`)
