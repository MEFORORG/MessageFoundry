- **A directory search that does not end with success is an outage, never "no such account".**
  Every LDAP search now refuses any result code but success, with or without entries: busy,
  unavailable, unwillingToPerform, adminLimitExceeded, a time or size limit, and noSuchObject on
  a missing search base. Before, such a search read as no entries, so the session reconciler would
  have struck a present account toward revocation, and a busy nested group search read as fewer
  groups. The reconciler now reads these as unavailable, which never revokes, and a sign-in writes
  `auth.login_error` naming the code. `check-privileges` names the code for the bind-account read.
  No directory diagnostic text reaches the error, the log or the audit row.
  **The cost:** a code that recurs on every pass, such as a deleted search base, now stops
  revocation and the role re-diff for as long as it lasts, with one WARNING per code per process
  and no latched alert. The nested group search is not paged. Where a directory caps an unpaged
  search (AD's MaxPageSize, 1000 by default), an account in more groups than the cap would end
  it with sizeLimitExceeded and could no longer sign in, where it used to sign in with a truncated
  group list. That was not measured against a domain controller. (vault `BACKLOG #3010`)
