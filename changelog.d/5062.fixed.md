- **The server-DB live-schema check reads more DDL forms, and raises on a form it cannot read
  instead of misreading it.** A multi-target `DROP TABLE` or `DROP INDEX` drops each name; a column
  rename (`RENAME COLUMN`, `sp_rename ... 'COLUMN'`) moves the column; a key written `(col)` reads
  as the column. An `ALTER TABLE` with more than one clause or an action it does not know, a table
  or index rename, and a `--` or `/*` inside a quoted string now raise in the unit test that reads
  each shipped batch. The Postgres index read now prints a key's collation, operator class and
  NULLS order, so an index built with one no longer passes as the bare key. The indexes the Postgres
  migration drops are no longer expected. A table that exists with no columns lists the columns it
  lacks instead of reading as missing. SQL Server runs neither catalog read for zero names, the
  batch is read before it runs, the refusal is logged without a doubled prefix, and the check's
  revision is one constant both backends hash, so a store marked by an earlier build takes the full
  run once more. (`BACKLOG #5062`)
