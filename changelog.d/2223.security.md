- **The SQL Server store's `[store].ssl_root_cert` pin now takes effect.** The store sent the
  pin as the ODBC `ServerCertificate` keyword beside `Encrypt=yes`. On the ODBC Driver 18.7
  build tested, the pin was enforced with `Encrypt=strict` and was not enforced with
  `Encrypt=yes`, where a pin naming the wrong certificate still connected. So the pin would not have pinned anything on a first
  deployment. With `ssl_root_cert` set, the store now sends `Encrypt=strict` with the pin. Strict
  encryption is TDS 8.0, so the pin needs SQL Server 2022 or later, the supported floor; an older
  server refuses the connection rather than taking an unenforced pin. Point the setting at the
  server's own certificate: the match is exact, so a CA file matches nothing. Do not count the
  pin as a revocation control. Unset, the store still sends `Encrypt=yes`, and the escaped dev
  posture is unchanged. (vault `BACKLOG #2223`; measured under `#3009`)
