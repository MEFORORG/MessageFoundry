- **An integer cap setting refuses a bool or a fraction instead of truncating it.** Every count or
  byte cap read through `int()` turned `True` into 1 and `1.9` into 1. A code-first call such as
  `MLLP(max_frame_bytes=1.9)`, or an `env()` reference cast to `float` or `bool`, would have built a
  listener with a one-byte cap that refuses nearly everything. A `connections.toml` literal was
  already refused at load. Now a bool, an infinity, a NaN and a fraction of one or more are refused
  at build, naming the key. **`False` is refused too**, where it used to read as "off": a bool is not
  a count, so write `0` or `None` to turn a cap off, as documented. A whole float such as `2048.0`
  still reads as 2048, and a fraction below one keeps the range message each setting already gave
  it. (`BACKLOG #3431`)
