- **An HTTP Digest challenge the engine will not answer now stops the outbound lane and keeps its
  queue.** The engine answers a Digest challenge only with SHA-256. When an endpoint or a web
  proxy sent one it would not answer, a REST, SOAP, FHIR or DICOMweb send reported "rejected an
  invalid request value", code `bad-request-value`. On a first deployment each queued message
  would have dead-lettered in turn, and the code would have sent an operator looking for a bad
  header and not for an authentication mismatch. The send now reports its own code,
  `auth-challenge-refused`. Under the default `credential_fault_policy = "stop"` the lane stops
  and every queued message stays pending, as it does for a refused FTP security mode. Under
  `"dead_letter"` the one message dead-letters with the new code. A test connection and a
  `fhir_lookup` read report the same fixed text. The refusal needs Digest set up on the
  connection, for the endpoint or for the web proxy. The refused challenges are at least these: a
  Digest challenge that names a hash other than SHA-256, and a malformed one. Other unanswered
  challenges do not raise it. At least one of them, a Digest challenge with an unsupported `qop`,
  still reads as unreachable and retries. A stopped lane stays stopped until a reload or a
  restart. See `credential_fault_policy` in [CONFIGURATION.md](../docs/CONFIGURATION.md).
