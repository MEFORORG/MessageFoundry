- **A proxy URL that carries credentials is refused unless it is written `https://`.** `urllib`
  sends a `user:password@` from a proxy URL to the proxy as a `Proxy-Authorization: Basic` header,
  in cleartext. Such a proxy is now refused before each request, whether it comes from `proxy_url`,
  from `HTTP_PROXY` or `HTTPS_PROXY`, or from the system proxy settings. The Vault hop already
  refused this. Writing the proxy `https://` is not refused and does not protect the credentials:
  see [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #2572`)
