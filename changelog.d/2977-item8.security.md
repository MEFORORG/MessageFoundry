- **A REST destination with `ech_egress` and `verify_tls = false` is now judged by the revocation
  guard.** With an ECH sidecar the engine dials the loopback sidecar through a verifying opener
  whatever `verify_tls` says, and the sidecar makes the TLS connection to the peer, so
  `verify_tls = false` turned off no verification. It did turn off the revocation guard: an
  off-loopback hop on an enforcing instance built on `tls_hop_attested` alone, while the same hop
  with `verify_tls` on was refused unless `tls_revocation_attested` was set with its reason. That
  hop is now refused the same way, and its refusal offers the same attestation. A direct
  `verify_tls = false` hop, with no sidecar, is unchanged. (`BACKLOG #2977`)
