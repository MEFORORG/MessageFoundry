- **A credential a generic ODBC connection string sends without braces is now hidden whole in a
  log line.** A password sent plain to a driver the engine has not measured, and every
  `odbc_params` value, `sslpassword` among them, may hold a space, `,`, `&` or, for a password,
  `=`. The log scrubbers stopped at the first three, so an echoed `;PWD=...;` would have printed
  the tail of the password, and `;sslpassword=...;` would have printed whole, since `ssl` glued to
  `password` gave the label no word boundary. A member right after a `;` whose key ends in a
  credential word, or in `token` (the builder's own secret keywords), such as `AccessToken`, now
  has its value taken to the next `;`, on the write-time log filters and in
  the support bundle and `GET /logs/tail`. Where that value would run into a later label's
  quoted or braced value, or into a URL, the old reading applies instead. The cost is
  over-redaction: text after a glued `;password=` in prose is hidden to the next `;` or the end of
  the line. A credential that is the FIRST member, with no `;` before it, is still read as
  before. (BACKLOG #5030)
