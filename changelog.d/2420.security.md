- **A backup's sweep of its own DR staging root takes only this account's directories.** A
  server-DB store stages in `.mefor-staging` under `[backup].destination`, which inherits whatever
  the destination grants. The backup swept it with no owner filter, so another account able to
  write there could plant a `mefor-backup-*` directory holding a lock file and a marker, and have
  the teardown run on a tree it controls. The backup now opens its own staging directory first and
  sweeps only directories with that directory's owner, as its sweep of the OS temp dir and a
  standalone verify already did. On Windows an elevated process's owner is Administrators, so
  elevated runs of different administrator accounts still share one owner there.
- **The staging teardown's truncate fail-safe empties the file it checked, never a name.** It
  used to check each file with `lstat` and then open it by path, so a name swapped for a link or a
  hard link, or a parent directory swapped for a junction, between the check and the open would
  have had the engine truncate a file outside the directory. On POSIX it now walks by directory
  descriptor with `os.fwalk` and opens each file with `O_NOFOLLOW`. On Windows it opens the
  directory and each file without following a reparse point, and refuses a file whose final path
  lies outside the directory. On both, the open handle must be a regular file with one link before
  it is truncated. A hard link made after that check still names the file the engine checked, so
  that file is emptied under the new name too. ([`docs/PHI.md`](../docs/PHI.md), section 2.)
