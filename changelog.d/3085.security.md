- **A repeat reconciler revocation of one account is audited, and a disabled or absent
  account's still alerts.** In the shipped code, two reconcilers on one store could both revoke
  one account. Each wrote a row and raised an `ad_session_revoked` alert. For any reason but a
  scope change, each also sent the user a notice. The second ended nothing. Now a revocation that
  ended no session and changed no role still writes its `auth.ad_session_revoked` row, with
  `sessions: 0` (owner ruling 2026-10-16, "audit always"). When the directory says the account is
  disabled or absent, it still alerts and sends its notice, as when the user signed out mid-pass
  (owner ruling 2026-10-17), and so does a repeat revocation of such an account: no audit row
  decides whether a revocation alerts, because a row the pass did not write could be forged to
  silence it (vault BACKLOG #3750 item 33). Any other revocation that ends nothing is quiet,
  unless its own row is refused. If both reconcilers read the old roles, both still report. If
  the first reconciler's pass ended before it alerted, a quiet repeat revocation leaves the
  account paging nobody. Vault BACKLOG #3085, item 2.
