- **A repeat reconciler revocation of one account is audited, and alerts only when the directory
  says the account is disabled or absent.** In the shipped code, two reconcilers on one store
  could both revoke one account. Each wrote a row and raised an `ad_session_revoked` alert. For
  any reason but a scope change, each also sent the user a notice. The second ended nothing. Now a
  revocation that ended no session and changed no role still writes its `auth.ad_session_revoked`
  row, with `sessions: 0` (owner ruling 2026-10-16, "audit always"). When the directory says the
  account is disabled or absent, it still alerts and sends its notice, as when the user signed out
  mid-pass (owner ruling 2026-10-17), and that holds for a repeat revocation too. No audit row
  decides it, because a row the pass did not write could be forged to silence the alert (vault
  BACKLOG #3750 item 33), so two reconcilers revoking such an account both alert. Any other
  revocation that ends nothing is quiet. If both reconcilers read the old roles, both still
  report. If the first reconciler's pass ended before it alerted, a quiet repeat revocation leaves the
  account paging nobody. Vault BACKLOG #3085, item 2.
