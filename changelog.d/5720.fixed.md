- **A store open that fails or is cancelled closes everything it opened, and settles the AES-GCM
  invocation block it reserved.** On PostgreSQL and SQL Server the failed-open cleanup now also
  runs on a cancel, and goes through the store's own close steps, so the block reserved at open is
  settled rather than forfeited. No backend settles a cipher its open had not yet bound to the
  store's salt, since that cipher may count for another store or for none. On SQL Server a cancel
  while the pool dials releases its executor. On SQLite a read-pool connection is tracked before
  its first PRAGMA. On all three backends a close, and a failed open's cleanup, run every teardown
  step whatever an earlier step raised, and run to completion through a cancel: nothing is bounded
  until a cancel arrives, and then everything left, the settle included, shares one 10-second
  deadline, past which the teardown is cancelled and the cancel is raised. A close or open
  coroutine closed mid-way runs a synchronous teardown. These failure paths log at WARNING by
  exception class, with any traceback at DEBUG only. (`BACKLOG #5720`)
