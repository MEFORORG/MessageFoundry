- **A store open that fails or is cancelled closes everything it opened, and settles the AES-GCM
  invocation block it reserved.** On PostgreSQL and SQL Server the failed-open cleanup now also
  runs on a cancel, and goes through the store's own close, so the block reserved at open is
  settled rather than forfeited. No backend settles a cipher its open had not yet bound to the
  store's salt, since that cipher may count for another store or for none. On SQL Server a cancel
  while the pool dials releases its executor, and a close whose claim-holder teardown raises still
  closes the pool. On SQLite a read-pool connection is tracked before its first PRAGMA, so a
  PRAGMA that fails no longer leaves its worker thread running. On all three backends a cancel
  that arrives while the cleanup runs waits for it, up to 30 seconds, and is raised after.
  (`BACKLOG #5720`)
