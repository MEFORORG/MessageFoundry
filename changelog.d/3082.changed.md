- **A directory refusal at the second factor or a step-up names the fix for its cause.** When a
  directory refuses an account at `/auth/mfa-verify` or `/me/reauth`, the proof is not checked and
  the 403 now has one text per fix. A role the account lost in the directory since it signed in is
  told to sign out and sign in again, which takes the roles its groups grant now. Every other cause,
  an outage included, is told to try again later and, if it is still refused, to ask an
  administrator, never to sign out, since a new sign-in would fail the same way. A group-to-role
  map that fails its seal is in that second group, audited as `directory_role_map_unsealed`: a new
  sign-in reads the same map, and an administrator re-saving it is the fix. The identity provider
  step-up leg has its own texts for a demotion and an unsealed map. No text names a group or a
  role.
  `Elevation` gains `directory_refusal`, a `DirectoryRefusal`, and `directory_unconfirmed` is now
  derived from it. (`BACKLOG #3082`)
