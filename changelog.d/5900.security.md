- **A correct re-auth password on a session the ceremony loses no longer clears the account's
  lockout counters or raises a login-after-failures notice.** The causes covered include at least
  a session revoked under the ceremony, one whose stamp fails its seal, and one whose rotation
  fails. Each answers `session_lost`, and the counters stay as the failures set them. On a kept
  session the clear is a compare-and-set in the store, written only while the account still holds
  the lockout and identity state the proof read, so a failure, lock, disable or re-bind committed
  meanwhile by any writer is kept; an account gone, disabled or re-bound by then is granted
  nothing. The re-auth's audit rows commit with the clear, and a raise after a correct proof still
  writes its `auth.reauth` row. What holds is stated once in `docs/SECURITY.md`, under
  *The password re-auth leg's lockout clear is a compare-and-set*. (`BACKLOG #5900`)
