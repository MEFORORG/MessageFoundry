- **No setting can turn sign-in off, in a config file or in code (vault BACKLOG #2825).**
  `AuthSettings.enabled` is gone. Since vault BACKLOG #2719 no file or environment variable could
  set it, but an embedder building settings in code still could. Settings now always build an auth
  service, and a built `AuthService` always requires a session: its `enabled` is a read-only
  `True`. The only way an app runs without sign-in is the app factories' `allow_no_auth=True` with
  no auth settings and no service. Before this, an embedder could attach a disabled service beside
  that opt-in. `create_managed_app` now refuses `allow_no_auth=True` beside any `auth_settings`.
  The security loosening report names the plain-LDAP, new-address step-up and sign-in limit entries
  without a sign-in gate, since there is no longer a sign-in-off state to hide them. `serve` was
  already always signed in, so a deploying site would see no change.
