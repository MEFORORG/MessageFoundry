- **The DATABASE connector bounds each statement with `statement_timeout`.** `Database(...)`,
  `DatabasePoll(...)` and `DatabaseLookup(...)` take `statement_timeout`, in whole seconds,
  `0` for no limit. Unset, it is 30 on the SQL Server preset and `0` on the generic dialect, so a
  default generic connection sets nothing. Every borrow applies it as pyodbc's connection `timeout`, so a hung
  statement fails transiently with `HYT00` rather than holding its connection, lane, poll or a stop
  without bound; a driver that refuses the value fails the borrow as a configuration fault naming
  the setting, on either dialect; a transient driver state from that write retries and discards
  the connection instead. Each DATABASE pool also runs aioodbc's driver calls on its own thread pool,
  sized `pool_max + 4`, rather than the event loop's default executor. A `DatabaseRef` reference
  sync sets no statement timeout. See
  [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #5756`)
