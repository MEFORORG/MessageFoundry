- **Signing out everywhere else no longer makes a missed session usable again.** A revoke that
  keeps the caller's session, per account or across every account, now stamps the new session
  epoch onto that session only when it carried the epoch the revoke's own raise replaced, read
  under the account's lock. A session an earlier sweep missed carries an older epoch, so it stays
  refused; where the account's record fails its seal, nothing is stamped. Same on SQLite,
  PostgreSQL and SQL Server. See [SECURITY.md](../docs/SECURITY.md), *Limits of the session
  sweep*. (`BACKLOG #4975`)
