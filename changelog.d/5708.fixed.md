- **A loopback row whose correlation cannot be read is now dead-lettered rather than wedging its
  lane, and a reload during its transform no longer reads as a Handler error.** The transform
  stage read a re-ingressed row's metadata before its error handling, so metadata that did not
  decrypt or was not JSON, a correlation id that was not a string, or a captured reply that did not
  decrypt would have been taken as an infrastructure fault and re-pended at the head of the
  strict-FIFO lane on every pass. Each now dead-letters the row, which stays replayable, on the
  split and the fused (SQL Server) paths alike. The stage also read the graph live after those
  reads, so a reload that dropped the inbound or the handler in that window would have reached the
  internal-error policy as a Handler fault and dead-lettered an ACKed message. The row now finishes
  under the graph it started with.
