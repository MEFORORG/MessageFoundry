- **`admin-unlock`, `admin-set-notify-email`, `admin-reset-totp`, `store attest-transit-bound`,
  `store withdraw-transit-bound`, `audit-verify`, `audit-anchor`, `rotate-key` and `backup` now
  open the store with the instance's hop posture, as `serve` does.** They passed none. On a first
  deployment at `[security].enforcement = enforce`, each would have crossed an off-box PostgreSQL
  store hop with no revocation check, which `serve` refuses. Each now refuses it and exits 2. At
  `warn` they now follow the dial as `serve` does, so this change LOOSENS there:
  `MEFOR_ALLOW_INSECURE_TLS` is honoured on a weakened store and an unattested off-box Vault
  crosses with a WARNING, where with no posture each was refused. An unrevoked store hop crosses
  there with a WARNING too; with no posture it crossed silently.
  **Exit codes change:** a hop refusal (`InsecureHopRefused`) raised while one of these commands
  opens the store now exits 2, could not start, where it reached the dispatch floor's exit 1. A
  weakened-TLS refusal is a bare `ValueError` and still exits 1. A key refusal at `backup`'s open
  keeps BACKLOG #3471's text and exit 2; a key error from the backup runner's own key resolution
  is still `backup failed`, exit 1. Each of these commands renders a key or hop refusal at its
  open through `codec_safe_str`, so a key source's codec error does not quote a byte it decoded. ([SECURITY.md](../docs/SECURITY.md), `BACKLOG #2532`)
