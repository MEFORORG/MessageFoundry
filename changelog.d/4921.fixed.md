- **A DATABASE source stops a poll at the first row whose handler fails.** The shipped code went
  on to the next row, so with a high-water-mark `mark_statement` that row's mark advanced the
  cursor past the failed row, and no later poll would read it again. Now no later row of that poll
  is handed off or marked, and the next poll starts from what is still unmarked; a high-water mark
  relies on `poll_statement` returning rows in cursor order for this. The trade-off is
  head-of-line blocking: a row whose handler fails every time holds back the rows behind it, so
  each failure now also emits a `handler_error` connection event, whose reason renders the error
  as the log line does: a driver error as its type, SQLSTATE and native error number. See
  [CONNECTIONS.md](../docs/CONNECTIONS.md#database-source--databasepoll). (`BACKLOG #4921`)
