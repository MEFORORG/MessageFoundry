- **A Vault Transit outage on an uploaded file answers 503, not 423.** Under
  `[store].cipher_provider = "vault_transit"`, a Transit call on the data key that got no verdict
  (the connection failed or timed out, or Vault answered 429, 500, 502 or 503) now raises
  `CipherUnavailableError`, a `CipherError` subclass. The upload routes answer it **503** with
  `Retry-After`, where they answered 423 and named `rotate-key` for a file that was fine, and an
  upload during the outage answers 503 rather than 500. Nothing is stored or removed. A value
  Transit refuses, a failed tag among them, still answers 423, and a caller who would get 404 still
  gets 404. See [PHI.md](../docs/PHI.md) section 3. (`BACKLOG #3734`)
