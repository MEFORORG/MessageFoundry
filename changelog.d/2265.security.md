- **The tee anonymizer now applies a rule that names an MSH field.** It used to skip every MSH
  rule, while its leak-check counted the field of such a rule on a later MSH line as scrubbed. So
  a dashed SSN in a second MSH line's field, named by a `drop` in `anon.toml`, would have stayed in
  the output of `python -m tee anonymize-captures` and passed the check. The engine anonymizer
  already applied the rule. The tee now rewrites the field on each MSH line, the header included,
  as the engine does. No default rule names an MSH field, so output changes only for an overlay
  that maps one. **Breaking for such an overlay:** a rule that would rewrite `MSH-0`, `MSH-1` or
  `MSH-2` is now refused by both anonymizers, because `MSH-1` and `MSH-2` hold the message's
  delimiters. Before, the tee ignored it and the engine could emit a header with no readable
  delimiters. A `keep` on either is still allowed. **This does not make the two anonymizers agree
  on every input.** [PHI.md](../docs/PHI.md) section 9 names at least two engine-side gaps, for a
  `BHS` or `FHS` line and for a short later header line, that this change leaves open.
  (`vault BACKLOG #2265`)
