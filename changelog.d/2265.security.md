- **The tee anonymizer now applies a rule that names an MSH field.** It used to skip every MSH
  rule, while its leak-check counted the field of such a rule on a later MSH line as scrubbed. So
  a dashed SSN in a second MSH line's field, named by a `drop` in `anon.toml`, would have stayed in
  the output of `python -m tee anonymize-captures` and passed the check. The engine anonymizer
  already applied the rule. Both now rewrite the field on every MSH line, the header included, and
  give the same bytes. No default rule names an MSH field, so output changes only for an overlay
  that maps one. **Breaking for such an overlay:** a rule that would rewrite `MSH-1` or `MSH-2` is
  now refused on both sides, because those fields hold the message's delimiters. Before, the tee
  ignored it and the engine could emit a header with no readable delimiters. A `keep` on either
  is still allowed. See [PHI.md](../docs/PHI.md) section 9, which also names two engine-side gaps
  for a later `BHS` or `FHS` line that this change does not close. (`vault BACKLOG #2265`)
