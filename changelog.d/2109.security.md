- **`rotate-key` refuses `vault_transit` mode before it touches anything.** Under
  `[store].cipher_provider = "vault_transit"` no run of the command can rotate a value, because the
  store's re-encrypt pass refuses the Transit cipher. The command used to learn that late. With a
  local key set, it resolved the key, dialled Vault and opened the store writable, and only then
  exited 2. With none, it told the operator to set `MEFOR_STORE_ENCRYPTION_KEY`, which the Transit
  cipher never reads. It now exits 2 first, with no key read, no Vault call and no store open. The
  refusal says to rotate the Transit data key's version in Vault instead, and not to raise its
  `min_decryption_version` past a version that still seals a value or MACs an audit row. The
  Transit cipher's refusal of an in-process value no longer tells the operator to rotate the store
  into Transit: no command does that, or moves Transit ciphertext between keys, yet.
  (vault `BACKLOG #2109`)
