- **The MLLP frame deadline now starts on the first byte of any kind, and a cut-short stop still
  clears the per-host counts.** `max_frame_seconds` on an `MLLP()` inbound used to start only on a
  frame's start byte. Bytes outside a frame reset the idle bound but never started the deadline, so
  on a first deployment a peer trickling them would have held a slot with no frame deadline. The
  clock now starts on the first byte after the last completed frame, as it already did on raw TCP and
  X12, and runs on the same shared clock. A completed frame still stops it, so a feed that sends
  whole frames and then goes quiet is left to `receive_timeout`. One visible effect: a lone trailer
  byte that arrives in its own read starts the clock, so where `receive_timeout` is longer or off, a
  peer that then goes quiet closes at `max_frame_seconds` with a `frame_deadline` reason. The MLLP
  `stop()` also clears the per-host connection counts in a `finally`, so a stop that is cancelled or
  fails in its client wait no longer leaves a stale count that would refuse that address early after
  a restart. See [CONNECTIONS.md](../docs/CONNECTIONS.md).
