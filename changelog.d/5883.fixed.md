- **A field-path message search reads past the first value.** A search on a path such as `OBX-5`
  or `PID-3.1` now tests later segment occurrences and field repetitions, so it can select more
  messages than before, inside the caller's channel scope. That covers message search, a saved
  preset's search, an export by search criteria, and upload browse. A later occurrence holding only
  delimiters does not count as present. Known limits, at least: a stray escape character, or a
  repetition character the header did not declare or shares with another separator, limits a field
  to its first repetition; a later header declaring other separators, or a malformed header-like
  line, ends the walk. A search can still under-report such a message. (`BACKLOG #5883`)
