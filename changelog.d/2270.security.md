- **A trust anchor that names an encryption header now refuses.** A `Proc-Type:` or `DEK-Info:`
  header name, in any case, anywhere after the first `-----BEGIN ` of the text the engine would
  load, refuses before the TLS library sees that text. That is inside a block of any kind, and in a
  comment between blocks or after the last one. A comment line that is not ASCII is dropped before
  the check. This holds for the `[api]` and `[auth]` anchor files and an inbound connection's
  `tls_ca_file`, at start and at every reload that is not a dry run; an outbound connection's
  `tls_ca_file` is still loaded by path. A private key encrypted in the legacy header format
  refuses with it. A PKCS#8 `ENCRYPTED PRIVATE KEY` block has no such header and still loads. On
  an encrypted certificate block the library could otherwise wait for a password, so a start or
  reload could hang. (`BACKLOG #2270`)
