- **A trust anchor that names an encryption header now refuses.** A `Proc-Type:` or `DEK-Info:`
  header name, in any case, anywhere after the file's first `-----BEGIN `, refuses at start and at
  reload, before the TLS library sees the file. That is inside a block of any kind, and in a
  comment between blocks or after the last one. A private key encrypted in the legacy header format
  refuses with it. A PKCS#8 `ENCRYPTED PRIVATE KEY` block has no such header and still loads. On an
  encrypted certificate block the library could otherwise wait for a password, so a start or
  reload could hang. (`BACKLOG #2270`)
