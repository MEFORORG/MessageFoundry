- **OIDC sign-in refuses an id_token whose `azp` is present and is not exactly the configured
  client id, whatever its audience count.** That covers another client's id, null, an empty
  string and any non-string value. The check used to run only on a token with more than one
  audience. A malformed `aud` (an array with a non-string or empty element, or an empty string) is
  refused too, even when it also names the configured client. Refusing a non-string element follows
  RFC 7519; refusing an empty audience goes beyond it. The engine still has no trusted-audience
  list, so a token whose `aud` names the client and another audience is accepted when `azp` is the
  client id; OpenID Connect Core ID Token Validation item 3 says to reject an untrusted extra
  audience, and this release does not close that gap. (`BACKLOG #5339`)
