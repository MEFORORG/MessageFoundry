- **A connection-event kind outside the one declared vocabulary is refused.** The kinds live in
  the new `messagefoundry.connection_events` module, which `transports/base.py` re-exports and the
  web console's event-log filter reads, so the console no longer keeps its own list. The runner
  drops an undeclared kind before the event is queued, so it never joins a burst and the declared
  events around it are all written. It logs a WARNING naming the connection and the kind, at most
  once a minute per pair and within a cap across pairs, and each line reports how many such
  events the runner has dropped so far. All three store backends also raise `ValueError` on an
  undeclared kind, as the backstop for any other writer. CI asserts that every literal emit site
  of the shapes it walks uses a declared kind. The `SourceConnector` and `DestinationConnector`
  docstrings now state the never-accept-and-drop rule and what a source does when its inbound
  handler raises. (BACKLOG #1624)
