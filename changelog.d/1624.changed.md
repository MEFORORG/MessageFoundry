- **The store refuses a connection-event kind outside the one declared vocabulary.** The kinds
  live in the new `messagefoundry.connection_events` module, which `transports/base.py`
  re-exports and the web console's event-log filter reads, so the console no longer keeps its own
  list. All three store backends raise `ValueError` on an undeclared kind. The runner's
  connection-event drainer then re-writes the burst row by row, so a lone undeclared row costs that
  row; a run of them can also cost the declared rows behind them in the same burst. CI already
  asserts that every literal emit site uses a declared kind. The `SourceConnector` and
  `DestinationConnector` docstrings now state the never-accept-and-drop rule and what a source
  does when its inbound handler raises. (BACKLOG #1624)
