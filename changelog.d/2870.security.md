- **A `Direct()` destination and the `[alerts]` email sender now hold their addresses to the
  `Email()` destination's rule and pass the SMTP envelope explicitly.** The sender must be one plain
  `local@domain`, and each recipient must read as one once a display name or group is dropped. `From:`
  and `To:` are built from the checked text, and the same text is handed to the SMTP client as
  `MAIL FROM` and `RCPT TO`, rather than being derived from a parse of the headers that decodes
  encoded words. Before this, an encoded-word or group address in the config would have moved the
  envelope on a first deployment. Direct checks at config load. On the alert side, `email_from`,
  `email_to` and each rule's `recipients` override are checked at startup and by `alert add`, and
  every send checks again, per-user security notices included. A user's notification address must
  now pass the same rule when it is set, so a notice to it cannot fail at send. A recipient entry
  holding a line break is now refused, by `Email()` and its `[egress]` check too, rather than sent
  with the break dropped. (vault BACKLOG #2870)
