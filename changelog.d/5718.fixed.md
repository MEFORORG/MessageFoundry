- **An X12 outbound's send-time cleartext-hop refusal now stops the lane and keeps the queue,
  and a reload no longer leaves an X12 send running on the replaced connector.** The refusal is
  now the permanent configuration fault (`insecure-hop-refused`) MLLP and the HTTP family raise,
  where it was a bare `InsecureHopRefused` the delivery worker would have dead-lettered row by
  row. A send that reaches an X12 connector a reload already closed retries on the replacement,
  and closing the connector also closes a connect-per-send in flight, as it closed the persistent
  connection. (`BACKLOG #5718`)
