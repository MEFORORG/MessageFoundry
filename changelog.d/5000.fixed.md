  A weakened store hop (`trust_server_certificate` on or `encrypt` off, on PostgreSQL or SQL
  Server) the escape does not cover, a SQL Server `[store].ssl_root_cert` pin the engine must not
  send, and a PostgreSQL `[store].ssl_root_cert` or `[store].ssl_crl_file` the open refuses, were
  refused with a bare `ValueError`. In the shipped code that reached the CLI's error floor and
  exited 1, the code `audit-verify` keeps for a broken audit chain, so a job reading only the code
  would have reported a refused hop as tampering. Each is now a typed refusal, which `audit-verify`
  and the other store commands report as could not start, exit 2, when the open raises it. A
  broken chain still exits 1. (`BACKLOG #5000`)
