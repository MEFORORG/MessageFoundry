- **On Windows, the DR staging truncate fail-safe now holds each directory open while it empties
  the files in it, and checks a cloud or deduplicated file before letting its filter serve it.**
  Before, it closed each directory's handle before opening that directory's files by path, so a local
  account able to rename entries in the staging directory had a window to swap one for a junction.
  It also reopened a reparse point that names no path through its filter, which can recall or
  hydrate it, before checking the file had one link. It now uses the file connector's own Windows
  helpers, so the staging root and every directory down to the one being emptied cannot be renamed
  until its files are done, and a file with a second link is refused before any filter acts.
  Error 1, 50 or 87 from an open is no longer logged as a volume that cannot report a file's final
  path, and a subdirectory that cannot be opened is reported by its own name, not the staging
  root's. On a first deployment, these defects would have applied to a backup or verify whose
  staging directory could not be removed (BACKLOG #4992).
