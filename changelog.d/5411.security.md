- **The IDE Security Settings editor checks the file it writes and the numbers it saves.** A
  `messagefoundry.serviceConfig` set in workspace settings must name a file inside the workspace
  folder, and a path inside it must not leave through a symbolic link; a path set in user
  settings may name a file elsewhere. One that reaches the workspace folder by an alias gets the
  same link rules where realpath resolves the alias to the folder: at least a link, a subst drive
  or an 8.3 short name. An alias realpath does not resolve to it is not caught: at least a
  network-mapped drive (`net use`), since realpath returns its UNC form, a UNC loopback or
  admin-share spelling (a link to one included), a bind mount or a firmlink. In an
  untrusted workspace the editor refuses before it reads any file. Each CLI value is bound to its
  flag with `=`, and the host checks a save message's shape before it writes. A cleared number
  field now resets the switch to its secure default instead of saving 0, which for message-body
  retention meant keep indefinitely, and Save refuses a fraction, unparseable text or a retention
  value below 0.
  (`BACKLOG #5411`, `BACKLOG #5412`)
