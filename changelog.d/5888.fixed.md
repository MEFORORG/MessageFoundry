- **A DR restore-verify or restore no longer stalls the engine on a slow read-only key provider,
  and a DR activation's takeover timeout can now fire on one.** The `auto`, `env`, `dpapi` and
  `vault` providers resolve the keyring in their own thread. The timeout ends the wait, not that
  thread: it runs until the provider returns, holds a worker in the shared thread pool, and holds
  process exit until then. Under the `host` provider the keyring still resolves on the event loop,
  because that resolve can convert and delete a custody handoff, so no timeout can fire on it. A
  scheduled or on-demand backup also still resolves its key on the event loop, so a hung provider
  there still stalls the engine. (`BACKLOG #5888`)
