- **`audit-verify` no longer reports a keyed chain it could not check as a broken one.** Run from a
  shell that holds no store key, it exited 1, the code `docs/SECURITY.md` reserves for a broken
  chain. A scheduled job that reads only the exit code would have reported tampering on an intact
  log. It now exits 4 and prints a `NOT CHECKED` line saying no key is available. The store's verify
  sets this with a flag, never by matching text, and only in a process that holds no key, so a
  verify run with the key still exits 1 on any tampering. Without a key it still checks the sequence
  numbers and any expected anchor, and a break there exits 1. A store key the settings name that
  cannot be resolved, such as `vault_transit` with no Transit key named or an unreadable key file,
  now exits 2 (could not start) from `audit-verify` and `audit-anchor`, where it reached the
  dispatch floor and exited 1. Vault BACKLOG #2725.
