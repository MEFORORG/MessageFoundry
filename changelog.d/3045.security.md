- **A C0 control in an off-box audit record field no longer hides the text beside it, in the
  cases measured.** `json.dumps` escapes the 32 C0 controls before the log filters run, so on a
  first deployment a name, a credential or a date beside one, as in a typed sign-in name, would
  have reached the tee line unredacted. A text field holding a C0 control in the window
  the scrub scans is now scrubbed before it is encoded, and can ship as `[redacted]`; a control
  only past that window is not seen, and the `emit_audit_tee` docstring names the window. On each sink, the off-box forwarder
  included, read as passes of its installed filter chain, the line shows no
  word, a run of letters or digits, that the sink's line hid before this change, and parses
  as JSON wherever that line did; punctuation it hid can show. At least two things lose the
  scrub for a record, which then ships as it did before: a segment-shaped token such as `ABC|`,
  which a client can type, and the parse floor, where hiding the changed fields whole would
  leave a sink's reading unparseable where the line before parsed. The `emit_audit_tee`
  docstring says what is left. (`BACKLOG #3045`)
