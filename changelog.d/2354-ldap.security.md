- **BREAKING: `[auth].ad_allow_insecure_ldap` is inert under `[security].enforcement = enforce`.**
  It used to be honoured at any dial, so on a first deployment at the shipped `enforce` a plain
  `ldap://` `ad_server` would have sent the service-account and user passwords in cleartext. That
  config is now refused at load, and again when the authenticator is built, like every other
  weakened-TLS escape. Under `warn` the opt-in still works: it logs a WARNING at startup and
  `security_loosenings()`, the `serve` warning and `GET /security/posture` name it. Use an
  `ldaps://` server. ([SECURITY-LOOSENING.md](../docs/SECURITY-LOOSENING.md), vault `BACKLOG #2354`)
