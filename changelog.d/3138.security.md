- **`env(key, cast=bool)` now reads a boolean strictly.** It used Python's own `bool`, which reads
  any non-empty text as true. Every `MEFOR_VALUE_*` variable is text, so `false`, `0`, `no` and
  `off` all read as true. On a first deployment, an operator who wrote `false` would have turned on
  a loosening such as `tls_allow_expired` or `trust_server_certificate`, with nothing reported.
  At least the Rest, FHIR, SOAP, MLLP, DICOM and Ftp factories take the first, and the Database
  family takes the second. `cast=bool` now uses the same cast as `connections.toml`'s
  `cast = "bool"`. `true`, `1`, `yes` and `on` read true, and `false`, `0`, `no` and `off` read
  false, in any case. A TOML `true` or `false` from `environments/<env>.toml` works as before.
  - **A value outside those eight spellings now stops the load.** An empty value, `y` or `enabled`
    used to load and read as Python's `bool` read it. Now the error names the setting and the key,
    never the value. Check each `cast=bool` value before you upgrade.
  - **A `default=` given with `cast=bool` is read the same way**, when the reference is made. A
    default of `"false"` used to reach the connector as text and read true. An unreadable default
    is refused, naming the key.
  - **A `verify_tls` that resolves to false now meets the refusals its literal form meets.** A
    DICOMweb `tls_ca_file` that nothing would read, and a SOAP client certificate offered to an
    unverified peer, are refused when the connection is built, not only when written as a literal.
  - **Not every route is strict yet.** An `env()` with no cast hands a boolean setting text, and
    a connector reads any non-empty text as true. A `str` cast does the same. A cast you write
    yourself, such as `cast=lambda s: bool(s)`, runs as written. Give a boolean setting
    `cast=bool`. The `int` and `float` casts refuse text they cannot read, but `int` turns a TOML
    `1.9` into `1` and a TOML `true` into `1`, and `float` accepts `nan` and `inf`. See
    [CONFIGURATION.md](../docs/CONFIGURATION.md). (`vault BACKLOG #3138`)
