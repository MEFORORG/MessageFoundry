- **`env(key, cast=bool)` now reads a boolean strictly.** It used Python's own `bool`, which reads
  any non-empty text as true. Every `MEFOR_VALUE_*` variable is text, so `false`, `0`, `no` and
  `off` all read as true. On a first deployment, an operator who wrote `false` would have turned on
  `tls_allow_expired` on a Rest, FHIR or SOAP hop, or `trust_server_certificate` on a Database hop,
  with nothing reported. `cast=bool` now uses the same cast as `connections.toml`'s
  `cast = "bool"`. `true`, `1`, `yes` and `on` read true, and `false`, `0`, `no` and `off` read
  false, in any case. A TOML `true` or `false` from `environments/<env>.toml` works as before. Any
  other value now stops the load with an error that names the setting and the key, never the
  value. Existing code-first configs need no change. The other builtin casts were checked. `int`
  and `float` refuse text they cannot read. `int` does turn a TOML `1.9` into `1` and a TOML
  `true` into `1`, and `float` accepts `nan` and `inf`. None of those flips a setting to its
  opposite, so they are unchanged. A cast you write yourself, such as `cast=lambda s: bool(s)`,
  still runs as written. See [CONFIGURATION.md](../docs/CONFIGURATION.md). (`vault BACKLOG #3138`)
