- **A failed SQL Server read no longer returns its connection to the pool with a transaction
  open.** When the rollback after a failed read fails, the store now discards the connection
  instead of recycling it, and raises the read's own error rather than the rollback's. On the
  cluster lease claim and renew, which hold the coordinator's leadership lock, the rollback is
  also bounded by `[cluster].lease_renew_timeout_seconds` (floored at 1 s); one that runs past it
  discards the connection, so a stalled rollback can no longer hold a stepdown off unbounded.
  The COMMIT after a claim is still not bounded. (`BACKLOG #5066`)
