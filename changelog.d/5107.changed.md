- **`messagefoundry check` no longer passes a fixture that expects `ERROR` on a strict-validation
  timeout alone.** A timeout says the validator was slow on that machine, not that the content is
  invalid, so the gate now fails that run and says it got a timeout. A content refusal the
  validator returned after the timeout still counts, so a slow runner does not fail a fixture
  whose expected `ERROR` is that refusal. A `.expect` sidecar may now read `ERROR <reason>`, which
  passes only when the run's error contains the reason, case-sensitively; a plain `ERROR` still
  passes on every other `ERROR`. The dry run's strict-validation clock also starts after `hl7apy`
  is warmed, so a preview does not count the process's cold import or its choice-group probe, nor,
  when the warm-up can parse the body's MSH, the version's library or the structure's reference
  table. The live listener is unchanged: its first validate of each after a start still counts
  them. (`BACKLOG #5107`)
