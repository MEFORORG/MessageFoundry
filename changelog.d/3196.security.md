- **A directory error at a Kerberos or federated sign-in no longer writes its text into the audit
  trail.** The `auth.login_error` row both sign-ins write for a directory error stored the error's
  text, which can carry what the caller or the directory chose, such as a referral's host or a
  value read after the Kerberos step accepted the caller's token. The row now holds the closed
  reason `directory_error` and names the code defines: the error's type, an unanswered
  operation's result code and ldap3's name for it, and the type of any error behind it. A fault
  raised during a directory lookup that ldap3 did not raise while reading the directory's response
  is now logged at ERROR as an engine defect, naming the module, line and function, where it read
  as a plain outage at WARNING; it still fails the sign-in closed. (`BACKLOG #3196`, `BACKLOG #3727`,
  `BACKLOG #3017`)
