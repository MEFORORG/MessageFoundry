- **The admin routes that refuse your own account now decide on the stored id, and each refusal is
  audited.** Reset-password, reset-mfa and both federated-identity actions compared only the path's
  id with the caller's. On the console's `/ui/users/{id}/` routes, which take the path as plain
  text, a store that compares ids case-insensitively (SQL Server) would have let an administrator
  reach their own account by spelling the id in another case, and so reset their own second
  factors. All six self-target guards, disable and delete included, now also compare the stored id.
  Each refusal also writes an `auth.self_target_refused` audit row on both planes, naming the
  actor, the route (`op`), the caller's id and address. Before, the JSON plane kept only the step-up
  grant row and the console kept nothing. See [SECURITY.md](../docs/SECURITY.md).
