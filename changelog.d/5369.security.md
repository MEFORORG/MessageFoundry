- **BREAKING: `zip_decompress` refuses more member names, on every platform.** An archive with a
  member name holding a colon (an NTFS alternate data stream on Windows), or a path component
  ending in a dot or space (which Windows drops), now raises `CompressionError`. So does a
  component `ntpath.isreserved` names: a reserved device stem such as `NUL`, `con.hl7` or `COM1`,
  or a character Windows refuses in a name. That arm deliberately over-refuses: of the reserved
  device stems, only `NUL` is rewritten on current Windows, and the others open as ordinary files.
  A `.hl7v2` member is now checked as HL7 v2 instead of accepted unchecked.
- **BREAKING: `archive_member_name_reason` refuses the same names by default.** It takes a new
  keyword, `windows_names`, default `True`. A caller that checks member names directly now gets
  these refusals too; `windows_names=False` keeps the earlier check, and the DR config restore
  passes it. (`BACKLOG #5369`)
