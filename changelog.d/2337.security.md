- **A vault_transit store now needs a recorded attestation of its AES-GCM bound to start under
  enforce.** The engine counts no encryptions on that cipher, so `messagefoundry store
  attest-transit-bound --reason` records who vouched for the Transit data key's rotation, and
  when, in a store row with its audit row in the same transaction. `serve` refuses to start under
  `[security].enforcement = enforce` when no row names the configured key, and warns under `warn`.
  `messagefoundry store withdraw-transit-bound` removes it, audited. `GET /security/posture`
  reports it. See [SECURITY.md](../docs/SECURITY.md). (`BACKLOG #2337`)
