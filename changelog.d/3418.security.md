- **A proxy credential is never sent over TLS that does not verify the proxy.** An `http` target
  sent to a credentialed `https://` proxy reaches it over TLS, with the opener's own context. On an
  `http://` destination with `verify_tls = false` or `tls_allow_expired = true`, that context does
  not fully verify, so the credential would have gone to an unauthenticated proxy. That send is now
  refused, and so is one on a context with no host name check. The rule is stated on
  [`ProxyCredentialsRefusedError`](../messagefoundry/transports/bounded_read.py). (`BACKLOG #3418`)
