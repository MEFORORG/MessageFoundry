- **The SQL Server store and the DATABASE connector build their TLS keywords in one place.** Each
  used to carry its own brace quoting and its own `Encrypt` and `TrustServerCertificate` tail. Both
  now call `messagefoundry/odbc_dsn.py`, and both build the same strings as before. Only the store
  sends a `ServerCertificate` pin. The shared code refuses a pin beside `encrypt = false` or
  `trust_server_certificate = true`, a shape no current caller can send, so a pin the connector
  gains later cannot go out on a hop that verifies nothing. (`BACKLOG #3714`)
