- **HTTP Digest runs as configured or the connection does not build.** A REST, SOAP or FHIR
  outbound with Digest now refuses at construction a static `bearer_token`, `basic_user`,
  `basic_password` or `Authorization` header beside it, and a signing header named
  `Authorization`: a connection configures exactly one HTTP credential. Where such a credential is
  sent, it would have replaced the Digest response on the wire, because urllib lets a request
  header override the one the Digest handler adds. A lone Basic half sends nothing on REST or FHIR,
  and is refused under the same rule. A REST outbound refuses `ech_egress` with Digest, which used
  to drop the Digest handler. An `http_auth` value other than `digest`, such as a typo, is refused
  instead of read as no auth. (`BACKLOG #5529`)
