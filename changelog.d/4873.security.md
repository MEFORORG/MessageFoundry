- **The SQL Server preset refuses a driver that is not a Microsoft SQL Server driver, and a
  `server` holding a comma or a backslash.** The preset sent `SERVER=<server>,<port>` with any
  `odbc_driver`. psqlODBC passes `SERVER` to libpq, which reads a comma as a list of hosts, so on
  the preset the port would have been read as a second host name, and a `server` holding a comma
  could name any host `[egress].allowed_db` never saw; the port the check compared would bind
  nothing. The `odbc_driver` must now be one of Microsoft's registered names, whole, or a path to
  the Microsoft ODBC Driver library. FreeTDS, the bare legacy `SQL Server`, vendor drivers that
  mention SQL Server and mixed names are refused, since nothing shows they read the preset's TLS
  keywords. A `server` holding a comma or a `\` is refused. The connection-string build and the
  egress check both refuse, on all four database factories; see
  [CONNECTIONS.md](../docs/CONNECTIONS.md) for when `messagefoundry check` runs them. Use
  `dialect="generic"` for another driver. (`BACKLOG #4873`)
