- **The SQL Server preset refuses a driver that is not a Microsoft SQL Server driver, and a
  `server` holding a comma or a backslash.** The preset sent `SERVER=<server>,<port>` with any
  `odbc_driver`. psqlODBC passes `SERVER` to libpq, which reads a comma as a list of hosts, so on
  the preset the port would have been read as a second host name, and a `server` holding a comma
  could name any host `[egress].allowed_db` never saw; the port the check compared would bind
  nothing. The `odbc_driver` name must now hold a SQL Server word and no PostgreSQL, MySQL or
  MariaDB word. FreeTDS is refused, since nothing shows it reads the preset's TLS keywords. A
  `server` holding a comma or a `\` is refused. The connection-string build and the egress check
  both refuse, so `messagefoundry check` does too, on all four database factories. Use
  `dialect="generic"` for another driver; see [CONNECTIONS.md](../docs/CONNECTIONS.md).
  (`BACKLOG #4873`)
