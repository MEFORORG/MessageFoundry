- **A FILE source counts a rejected file it could not move against a separate per-poll budget.** An
  oversized, undecompressable, mistyped or scanner-rejected drop whose move to `.error` failed (a
  locked file, an unwritable `.error`, a read-only share) stays in place and is examined again on a
  later poll, but it was counted against `poll_max_files` as if it had been finished with. Such
  rejects sorting early would have spent the budget on each poll that examined them, holding back the
  healthy drops behind them. Such a reject, and at least a file changed during its read, a
  malfunctioning scan hook and a handler failure, now count instead against a second budget of the
  same size, which keeps the reads and pre-ingest scans of files left in place bounded per poll. A
  poll still stalls once that many stuck files sort first, and logs a WARNING;
  [CONNECTIONS.md, *Per-tick poll ceilings*](../docs/CONNECTIONS.md#per-tick-poll-ceilings) states
  the bound and that cost.
  (`BACKLOG #5717`)
