- **A `File(...)` source under `after_read` `move` or `delete` reaches healthy drops behind rejects it
  cannot quarantine.** A rejected file whose move to `.error` failed was read and charged against
  `poll_max_files` again on later scans, so enough of them sorting first could hold back the files
  behind them. Such a file is now remembered and retried in a bounded pass of its own after the
  other files, outside `poll_max_files`. This narrows that gap rather than closing it; the
  back-off rule at `STUCK_RETRY_SECONDS` in `transports/file.py` says when a retry falls due.
  `after_read = "leave"` is unchanged, and so is `Sftp(...)`/`Ftp(...)`. (`BACKLOG #5717`)
- **A `File(...)` source under `after_read` `move` or `delete` no longer hands off a processed file
  again on later scans because its move to `.processed`, or its delete, failed.** Such a file was
  read, handed off and charged against `poll_max_files` again on each later scan. It is now
  remembered like a reject that could not be quarantined. A retry reads it again, and, while its
  bytes match what was handed off, only moves or deletes it. A file that changed is handed off
  again. A restart of the connection, or a full memory, still hands it off again, as before. A
  remembered file that has not changed is now judged from the stat the directory listing already
  took, rather than a stat of its own. (`BACKLOG #5717`)
