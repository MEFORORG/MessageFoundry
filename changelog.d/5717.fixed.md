- **A FILE source no longer spends its per-poll budget on a rejected file it could not move.** An
  oversized, undecompressable, mistyped or scanner-rejected drop whose move to `.error` failed (a
  locked file, an unwritable `.error`, a read-only share) stays in place and is examined again on a
  later poll, but it was still counted against `poll_max_files`. Such rejects sorting early would
  have spent the budget on each poll that examined them, holding back the healthy drops behind them.
  Only a reject of which a copy reached `.error` counts now; one left in place is still logged each
  time it is examined.
  (`BACKLOG #5717`)
