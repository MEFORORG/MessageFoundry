- **A FILE source no longer spends its per-poll budget on a rejected file it could not move.** An
  oversized, undecompressable, mistyped or scanner-rejected drop whose move to `.error` failed (a
  locked file, an unwritable `.error`, a read-only share) stays in place and is examined again next
  poll, but it was still counted against `poll_max_files`. One that sorted early would have spent
  the budget on every poll, so the healthy drops behind it would never have been ingested. Only a
  reject that was archived counts now; the one left in place is still logged on each poll.
  (`BACKLOG #5717`)
