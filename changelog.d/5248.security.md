- **A reload names the fault when its config directory goes during the load.** A share lost after
  the reload's target check was audited as `invalid_config`, which sent an operator looking for a
  config to fix, though the target check audits the same fault as `unreadable`. A load that cannot
  read the config directory itself now refuses with its own `WiringError`, and an ungated reload
  audits that as `unreadable` with the target check's 422. That includes a directory that lists
  while `Path.is_dir` says no, and a listing fault in the trust check, which the load judges again
  by listing the directory: one gone is missing, and one that lists is still refused as a source
  the check could not vet. A released reload of a directory it cannot list is still refused as
  `digest_unavailable`. A config directory moved away before the Windows trust check read its
  owner and access list is now missing, audited `not_found`, where it was refused as a source the
  check could not vet and audited `invalid_config`; the refusal is logged at WARNING. Only a
  refusal that came from that read finding the directory gone is judged again. A policy refusal,
  such as a directory others can write or one with a foreign owner, stands whatever happens to the
  directory afterwards: it stays `invalid_config`, and a released reload keeps
  `approval_digest_check: not_reached`, even where the directory has since moved away or stopped
  listing. (vault `BACKLOG #5248`)
