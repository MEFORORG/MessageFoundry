- **A file that holds a key is created restricted, and `protect-key` fails closed.** The DPAPI
  store key file and every TLS private key the engine writes are now restricted in the call that
  creates them, so the file never carries the directory's inherited access. `protect-key` and the
  `cert` commands refuse to replace an existing file or link, and `protect-key --grant-account`
  refuses a broad group. If the file cannot be created restricted, the command exits non-zero,
  writes no file and prints no success line. `serve` and `supervise` now check the store key file
  and the TLS key the engine minted before using them, and refuse to start under
  `[security].enforcement = "enforce"` when a known broad group can read one
  ([PHI.md](../docs/PHI.md), "Key files", which also lists what the check does not cover).
  (`vault BACKLOG #2601`)
