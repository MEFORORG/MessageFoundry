  store key file and every TLS private key the engine writes are now restricted in the call that
  creates them, so the file never carries the directory's inherited access. `protect-key` and the
  `cert` commands refuse to replace an existing file or link. If the file cannot be created
  restricted, the command exits non-zero, writes no file and prints no success line. `serve` now
  checks the store key file and the TLS key it minted before using them, and refuses to start
  under `[security].enforcement = "enforce"` when a broad account can read one
