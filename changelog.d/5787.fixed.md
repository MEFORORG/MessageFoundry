- **An upload with no closing boundary delimiter line is refused.** A `multipart/form-data` upload
  body that ended before its `--<boundary>--` line was parsed, so a body that ended early was stored
  as a shorter file. It is now refused with HTTP **400**. A boundary delimiter now counts only on a
  line of its own, at the start of the body or after a CR or an LF, so boundary text in the middle
  of a line is file content, and a cut-short body whose file holds that text is refused too. A line
  before the close marker that starts with the boundary but is not a delimiter line, such as
  `--<boundary>--note`, is refused with HTTP **400** rather than taken as a delimiter. A file line
  that is exactly the close marker still ends the file. (`BACKLOG #5787`)
