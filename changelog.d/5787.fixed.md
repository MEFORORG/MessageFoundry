- **An upload with no closing boundary delimiter is refused.** A `multipart/form-data` upload body
  with no closing delimiter `--<boundary>--` was parsed, so a body that ended early was stored as a
  shorter file. It is now refused, with HTTP **400** where no size or part limit refuses it first.
  A boundary delimiter now counts only at the start of a line (at the start of the body, or after a
  CR or an LF), so delimiter text in the middle of a content line stays in the file, and a body
  whose only close marker sits mid-line is refused. A body whose first delimiter text does not
  start a line (a stray space or BOM before it, a preamble ending mid-line, or close-marker text
  mid-line in a preamble), which was parsed before, is now refused with HTTP **400** where no size
  or part limit refuses it first. A close marker followed on its line by anything other than spaces
  or tabs, such as `--<boundary>--note` or `--<boundary>--epilogue`, is no longer taken as the
  close, and the body is refused the same way. A content line that is `--<boundary>--` followed
  only by spaces or tabs is still read as the close, and one that starts with `--<boundary>` but
  not `--<boundary>--` is still read as a delimiter. (`BACKLOG #5787`)
