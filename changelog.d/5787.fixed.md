- **An upload that may be cut short is refused.** A `multipart/form-data` upload body that ended
  before its `--<boundary>--` line was parsed and stored as a shorter file. At least these are now
  refused with HTTP **400**:
  - a body with no closing delimiter line;
  - a line before the close marker that starts with the boundary but is not a delimiter line,
    such as `--<boundary>--note`;
  - a line after the close marker that starts with the boundary;
  - boundary text before the first delimiter line, such as a delimiter with a byte-order mark
    before it on its line, which would drop the first part;
  - in a body that closes, a part with no header block, or one whose `Content-Disposition`
    has no `name` or `filename` parameter, at any size.

  A delimiter now counts only on a line of its own: at the start of the body, or after a CR or an
  LF. Boundary text in the middle of a line is file content. A bare CR counts as a line break, so
  an HL7 segment start is a line start. Some cases still end a file early. At least these remain:
  a cut-short body whose file holds a close-marker line (`--<boundary>--`, padding allowed) is
  taken as complete, and so is one cut right after a line that only starts with the close marker.
  A split whose rest reads as a named part is kept as that part.

  A part's `Content-Disposition` is now read by one quote-aware tokenizer, and a parameter counts
  only by its whole key, so `x-name`, `x-filename`, `foo*name` and `filename*` are not `name` or
  `filename`. A text field carrying `x-filename="..."` is no longer taken as a second file part.
  A backslash in a quoted value escapes the next quote or backslash, as curl and httpx write
  them, so `filename="a\"b.hl7"` reads as `a"b.hl7`, not `a\`; any other backslash is kept.
  A value that ends in a backslash, as a browser sends one, such as `name="a\"; filename="b.hl7"`,
  still reads as before. A value is still read only when it is quoted, as before.
  (`BACKLOG #5787`)
