- **An upload that may be cut short is refused.** A `multipart/form-data` upload body that ended
  before its `--<boundary>--` line was parsed and stored as a shorter file. At least these are now
  refused with HTTP **400**:
  - a body with no closing delimiter line;
  - a line that starts with the boundary but is not a delimiter line, such as `--<boundary>--note`;
  - a line after the close marker that starts with the boundary;
  - boundary text before the first delimiter line, such as a byte-order mark before it, which
    would drop the first part;
  - a part with no header block, or with neither a `name` nor a `filename`, at any size.

  A delimiter now counts only on a line of its own: at the start of the body, or after a CR or an
  LF. Boundary text in the middle of a line is file content. A bare CR counts as a line break, so
  an HL7 segment start is a line start. Some cases still end a file early. At least these remain:
  a cut-short body whose file holds a close-marker line (`--<boundary>--`, padding allowed) is
  taken as complete, and a split whose rest reads as a named part is kept as that part.
  (`BACKLOG #5787`)
