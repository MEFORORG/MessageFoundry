- **An upload that may be cut short is refused.** A `multipart/form-data` upload body that ended
  before its `--<boundary>--` line was parsed and stored as a shorter file. At least these are now
  refused with HTTP **400**:
  - a body with no closing delimiter line;
  - a line that starts with the boundary but is not a delimiter line, such as `--<boundary>--note`;
  - a part with no header block, at any size. A file line that is a whole delimiter line leaves
    one, so that file is refused rather than stored short.

  A delimiter now counts only on a line of its own: at the start of the body, or after a CR or an
  LF. Boundary text in the middle of a line is file content. Some cases still end a file early.
  At least these remain: a file line that is a close-marker line (`--<boundary>--`, padding
  allowed) still ends the file, and a split whose rest holds a blank CRLF line reads as a part
  with headers. A bare CR counts as a line break, so an HL7 segment start is a line start.
  (`BACKLOG #5787`)
