- **An upload with no closing boundary delimiter is refused.** A `multipart/form-data` upload body
  with no closing delimiter `--<boundary>--` was parsed, so a body that ended early was stored as a
  shorter file. It is now refused with HTTP **400**. After the first delimiter, a boundary delimiter
  now counts only at the start of a line (after a CR or an LF), so delimiter text in the middle of a
  content line stays in the file, and a body whose only close marker sits mid-line is refused. A
  content line that starts with `--<boundary>` is still read as a delimiter. (`BACKLOG #5787`)
