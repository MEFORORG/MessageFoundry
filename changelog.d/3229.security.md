- **A directory role change that takes Administrator from its last enabled holder now raises an
  alert.** A directory sign-in's role sync and the session reconciler can take Administrator from
  an account, and neither goes through the console's last-administrator guard. By owner ruling 2026-10-13 the
  directory stays authoritative, so the change still applies. When it leaves no enabled
  Administrator, the engine now raises the `no_enabled_administrator` alert, keyed
  `user:<username>` with `via` set to `ad-sync` or `ad-reconcile`, and writes an
  `auth.no_enabled_administrator` audit row. At least two paths raise none: a console removal
  racing the demotion, and a failed count of Administrators. With none left, `provision-admin` runs again at the
  host. An `administrator_granted` alert for an account clears that account's
  `no_enabled_administrator` cooldown. It clears it only in the engine process that raises the
  `administrator_granted` alert. A reconciler re-grant raises no `administrator_granted` alert, so
  it leaves the cooldown in place. A directory disable or deletion of the last Administrator is not a
  role change, so it raises no `no_enabled_administrator` alert. A disabled account still counts as
  an enabled Administrator, so `provision-admin` still refuses. (`vault BACKLOG #3229`)
