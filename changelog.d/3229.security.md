- **A directory role change that takes Administrator from its last enabled holder now raises an
  alert.** A directory sign-in's role sync and the session reconciler can take Administrator from
  an account, and neither goes through the console's last-administrator guard. By owner ruling 2026-10-13 the
  directory stays authoritative, so the change still applies. When it leaves no enabled
  Administrator, the engine now raises the `no_enabled_administrator` alert, keyed
  `user:<username>` with `via` set to `ad-sync` or `ad-reconcile`, and writes an
  `auth.no_enabled_administrator` audit row. With none left, `provision-admin` runs again at the
  host. A grant of Administrator to the account, by a directory sign-in or in the console, ends
  that account's alert cooldown. It does so only in the engine process that made the grant. A loss
  raised in another engine process still waits out that process's own cooldown. A reconciler
  re-grant does not end the cooldown, and neither does an operator resolve. A loss that the
  cooldown no longer holds back can still go unpaged. At least a suspend on the alert, `mute =
  true`, or `transports = []` on the rule or on an `escalate` tier keeps it quiet. The grant does
  not reset the escalation count, so a later loss can reach a higher tier. A directory disable or
  deletion of the account is not a role change, so it raises no such alert. (`vault BACKLOG #3229`)
