- **`Message` now agrees with `Peek` on a fieldless bare segment.** A line such as `PID`, with no
  field separator, is no longer an occurrence anywhere in `Message`: `field`, `repetitions`,
  `count_segments`, `set`, `set_data`, `add_repetition` and group views skip it, as `Peek.field`
  always has. Before, reads and counts called the bare line occurrence 1 while an occurrence-1
  whole-field write skipped it, so on `PID` followed by `PID|1||X^Y~Q` a component write copied the
  bare line's empty field over the populated `PID`, and a write to a lone bare `PID` raised
  `KeyError` while `count_segments` reported it present. Every write now lands on the segment a Router reading with
  `Peek` sees, so a planted bare line cannot steer a Handler's default-occurrence scrub off the
  populated segment. A lone bare `PID` reads and counts as absent, and a write to it raises the
  normal missing-segment `KeyError`. `segments()` still lists every line, and `delete_segments`
  still removes a bare one. (`BACKLOG #5917`)
