- **The `[dicom]` extra now requires `pynetdicom>=3.0.4,<3.1`, where 0.5.1 allowed `<4`.** The
  DICOM listener runs its own association server, a subclass of pynetdicom's. It checks the peer
  address and bounds the TLS handshake in hooks that pynetdicom 3.0.4 calls. The listener already
  refuses to start on a pynetdicom that stopped calling them, but a site would only learn that at
  startup. The cap stops such a release at install time. No final pynetdicom 3.1 has been
  published, so the cap rules out no stable release. It does rule out the `3.1.0.dev0`
  development release on PyPI, which an install that opts into pre-releases could pick under the
  old cap. The lock already pinned 3.0.4, so no pinned version moves. (`vault BACKLOG #2713`)
