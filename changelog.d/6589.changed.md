- **The operator alert mutations and the connection flag refuse a missing audit row before they
  write anything.** `ack_alert_instance`, `resolve_alert_instance`, `suspend_alert_instance`,
  `resume_alert_instance` and `set_connection_flag` raise `TypeError` on `audit=None` as their
  first statement, on all three backends. Before, the refusal came after the write and the audit
  lock, and the change rolled back. (`BACKLOG #6589`)
- **`enqueue_ingress` now reads `origin_actor`.** An operator origin with no `origin_actor`, or a
  blank one, raises `TypeError` before anything is written, as an `origin_actor` given with any
  other origin does: the column names the user behind an operator origin only. The engine's
  `inject_message` types its `audit` as `InjectAudit`, whose return admits no `None`, since the
  store refuses a `None` row for an inject; so does the store's `enqueue_ingress`. (`BACKLOG #6589`)
- **A directory sign-in that creates the account's row records it.** The row commits with an
  `auth.ad_user_created` audit row, in the same transaction, naming the username and whether the
  sign-in was federated. Before, a first sign-in created the row with no audit row unless the
  directory's mail was not adopted. (`BACKLOG #6589`)
