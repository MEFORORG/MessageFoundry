- **A credential value no longer prints the tail of a later braced password, in the common shape.** A
  plain value under a `MEFOR_*`, token, session or `api_key` label ran on over a later `PWD=` (or other
  password-word label) whose braced value held a space, and stopped at that space, so the shipped log
  scrub and the support bundle would print the tail, for example `MEFOR_STORE_DSN=Server=h;PWD={p w}`
  gave ` w}`. The value now takes that label and its braced value, and writes the tail back with its
  words masked. The braces must hold no label and no character outside ASCII after their first white
  space, and the `{` must follow the `=` or `:` directly; anything else prints as before. At least
  these still print: `PWD= {p w}`, `%3BPWD={p w}`, a label glued on by `_`, a quote after the label,
  and a key-material or token label with a braced value. On the installed log chain a `token=` line
  still prints the tail, because the query filter runs first. Measured against the previous code on
  synthetic lines, the shared scrub and the support bundle: no ASCII line found prints a value the
  previous code hid. (`BACKLOG #2966`)
