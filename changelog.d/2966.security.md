- **A credential value no longer prints the tail of a later braced password, in the common shape.**
  A plain value under a `MEFOR_*`, token, session or `api_key` label ran on over a later `PWD=` (or
  other password-word label) whose braced value held a space, and stopped at that space, so the
  shipped log scrub and the support bundle would print the tail, for example
  `MEFOR_STORE_DSN=Server=h;PWD={p w}` gave ` w}`. The value now takes that label and its braced
  value, and writes the tail back with its words masked. What the braces must not hold includes at
  least a `;`, `,`, `&`, `{`, quote or line break anywhere in them, and a label, scheme word, `%` or
  character outside ASCII after their first white space, which must be a space or a tab. The `{`
  must follow the `=` or `:` directly, with only spaces or tabs between the keyword and that
  separator. Anything else prints as before. At least these still print: `PWD= {p w}`,
  `%3BPWD={p w}`, a label glued on by `_`, a quote after the label, and a key-material or token
  label with a braced value. On the installed log chain a `token=` line still prints the tail,
  because the query filter runs first. Code review found ASCII shapes where the change printed a
  value the previous code hid, and each one found is now refused; a random differential and a shape
  grid against the previous code are evidence on a sample, not a proof that no such line is left.
  (`BACKLOG #2966`)
