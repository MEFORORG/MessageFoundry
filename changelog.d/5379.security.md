- **The URL query credential detector reads bracket-keyed names.** It now drops every trailing
  index and reads each bracket key with the piece before it, so `user[password]`, `token[0][0]`
  and `user[password][x]` are named. Before, they passed at least the construction warning,
  `check`, the posture entry, the HTTP family's no-escape refusals, the settings-view URL mask and
  the rotation watcher's URL credential fingerprint unnamed. All of these now read the wider
  name test. The change also names
  ordinary bracket keys that end in a credential word, such as `filter[key]`, `include[auth]` and
  `meta[sig]`. A deploying site with such a URL on a hop that turns off TLS verification, or that
  sends plain `http` off the machine, would have that hop refused with no escape, as `filter_key`
  already is. (`BACKLOG #5379`)
