- **A passive DR standby no longer runs a backup pass.** A lone DR box always leads its own
  cluster coordinator, so with `[backup].enabled` it would have backed up its own store and written
  `dr_backup` audit rows. On a server-DB standby such a row would satisfy the live seed probe on a
  database nobody restored, and would become the latest anchor the `[dr].restore_token` check
  compares, refusing a valid restore. The engine's backup runner now runs no pass, scheduled or
  on demand, while the box is a DR standby that is not activated, and starts again once it is.
  The `messagefoundry backup` command is not gated. (`BACKLOG #5712`)
