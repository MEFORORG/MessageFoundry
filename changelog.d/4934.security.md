- **`rotate-key` now opens its rotation record, when it opens one, from a new `open_store` hook,
  `before_first_write`, which a writable open runs before its first write under the store key.** A
  read-only open does not run it. [PHI.md](../docs/PHI.md) and the `open_rotation_record` docstring
  give the conditions.
  **`serve` can now refuse to start on a changed store key the keyed audit chain cannot follow.**
  The refusal names its conditions and a remedy, and `docs/SECURITY-LOOSENING.md` names stores it
  does not cover. `[secret_rotation].allow_lost_audit_range_key = true` starts anyway, for a key
  that is truly lost; it logs the refusal as a WARNING, the chain breaks at that start's first
  audit row, and it is reported as a security loosening. Other commands that open the store and
  write an audit row, such as the `admin-*` commands, do not refuse.
  (`BACKLOG #4934`, `BACKLOG #4936`)
