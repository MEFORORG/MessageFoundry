- **`rotate-key` opens its rotation record inside the store open, before the open's first write
  under the key, on every store.** `open_store` takes a `before_first_write` hook, run on every
  writable open right after the store id pin check and before the salt bind, the cipher block
  reserve, the at-rest sweep and any audit row; a read-only open does not run it. A run killed
  anywhere after the hook leaves the record open, so the next `serve` start stamps nothing, on a
  store with no keyed audit chain too. The open's schema step runs before the hook, so a kill
  there leaves no record.
  **`serve` refuses to start when the store key differs from its stamp, or has none, the keyed
  audit chain has not been rolled to it, and the key the chain's current range is under is not
  configured.** That start's first audit row would break the chain. The refusal says to put the
  prior key back in `MEFOR_STORE_ENCRYPTION_KEYS_RETIRED` and run `rotate-key` until it exits 0.
  `[secret_rotation].allow_lost_audit_range_key = true` starts anyway, for a prior key that is
  truly lost; it logs the refusal as a WARNING, the chain breaks at that start's first audit row,
  and it is reported as a security loosening.
  (`BACKLOG #4934`, `BACKLOG #4936`)
