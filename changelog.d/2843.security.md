- **Three domain lists and the mail address check now share one host-name rule.**
  `[security].organization_domains`, `[security].external_link_allowlist` and
  `[egress].allowed_recipient_domains` each checked an entry's shape their own way. The two
  `[security]` lists refused only `/`, `:` and `*`, so they accepted entries that can never match a
  URL host, such as `-mx.example.org`, a non-ASCII domain or an address, and a partial address such
  as `0.1`, which would have matched every host ending in it. The egress list accepted
  hexadecimal IPv4 forms such as `10.0.0.0x1`, which the send rule refuses. All three now refuse at
  load whatever the address rule's domain check refuses: an empty label, a dot at either end, a
  hyphen at a label edge, a label over 63 characters, a non-ASCII domain, and a last label that
  does not start with a letter. A leading or trailing dot is refused rather than silently dropped.
  The two `[security]` lists still accept a dotted-quad IPv4 address such as `10.20.30.40`, because
  an identity provider can be reached by address, and the console now matches it exactly. Domain
  matching is unchanged: subdomains on a label boundary for the `[security]` lists, exact for
  recipient domains. (`vault BACKLOG #2843`)
