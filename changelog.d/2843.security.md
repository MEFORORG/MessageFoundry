- **Three domain lists and the mail address check now share one host-name rule.**
  `[security].organization_domains`, `[security].external_link_allowlist` and
  `[egress].allowed_recipient_domains` each checked an entry's shape their own way. The two
  `[security]` lists refused only `/`, `:` and `*`. So they accepted an address, a non-ASCII
  domain the console never matches, and a partial address such as `0.1`, which would have matched
  every host ending in it. The egress list accepted hexadecimal IPv4 forms such as `10.0.0.0x1`,
  which the send rule refuses. All three now refuse at load whatever the address rule's domain
  check refuses, as listed under `allowed_recipient_domains` in
  [CONFIGURATION.md](../docs/CONFIGURATION.md#egress). That includes any character other than
  letters, digits, hyphens and dots, so an underscore is refused. A leading or trailing dot is
  refused rather than silently dropped. The two `[security]` lists still accept a dotted-quad IPv4
  address such as `10.20.30.40`, because an identity provider can be reached by address, and the
  console now matches it exactly. Domain matching is unchanged: subdomains on a label boundary for
  the `[security]` lists, exact for recipient domains. (`vault BACKLOG #2843`)
