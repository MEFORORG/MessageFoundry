- **A backup's early sweep of its DR staging root goes by the owner a new entry there gets.** It
  went by the process's own owner. On a share whose server sets the owner, a directory carrying the
  process's owner may have been made by another principal, such as SYSTEM on the file server, and
  the sweep would have removed it. The backup now learns the owner from a probe it makes in the
  staging root and removes again, and sweeps by that owner. On POSIX the probe is an empty file
  created with `O_EXCL`, read through the descriptor that created it, so a rename in the staging
  root cannot choose the owner. When the probe cannot be created, as on a volume a killed run
  filled, the run logs a warning and sweeps by the process's owner only when the staging root
  itself carries that owner; otherwise that sweep is off for the run. A staging root that is itself
  the OS temp dir, such as a SQLite store kept there, is also swept by the backup's sweep of the
  OS temp dir, which goes by the process's own owner. What this leaves open is listed in
  [`docs/PHI.md`](../docs/PHI.md), section 2's staging row.
