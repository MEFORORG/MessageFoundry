- **`rotate-key` fails, and writes no key-rotation stamp, when it skips an uploaded file.** It used
  to print `OK`, exit 0 and write the ASVS 13.3.4 rotation stamp even when an uploaded file was left
  partly under the prior key, so an operator or a wrapper could retire a key that was still needed.
  It now prints `PARTIAL` and exits 1, and this run writes no stamp. `serve` still stamps a changed
  key on its own when it next starts, so the stamp alone does not show that a rotation finished.
  One upload that no configured key opens, or that cannot be written, no longer aborts the whole
  pass: it is left as it was and counted as a skip, and every other upload is re-sealed. An upload
  whose body is missing or is not text, under a sealed sidecar, is no longer counted as a skip,
  since no re-run can change it; `rotate-key` re-seals its sidecar and prints a note instead.
  (`BACKLOG #3181`)
