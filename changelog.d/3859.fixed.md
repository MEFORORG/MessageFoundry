- **A refused restart of a running listener now reads `failed`, and sends one alert.** A restart
  unbinds the listener before it starts it again. When a start gate, a hop guard, the startup
  directory check or the bind refused that start, the listener stayed down. It read `stopped`,
  had no failed record, and sent no alert, so nothing told an operator a feed that had been
  running was now down. The start path now records it failed, with one `connection_stopped`
  alert, as a refused trust anchor already did. A refused plain start is recorded the same way,
  as a start at boot records one. A second refused restart sends no second alert, so an alert
  rule that restarts the inbound cannot loop. A start that binds clears the record. A start of a
  connection that is not deployed is still refused without a failed record. (`BACKLOG #3859`)
