- **A float cap or timeout refuses a bool, a NaN, an infinity, or text that only rounds to zero.**
  Before this fix, a bare `float()` read `True` as one second and took `nan` and `inf`. A float cap
  such as `receive_timeout`, `idle_timeout_seconds`, `max_frame_seconds` or a
  `max_messages_per_second` rate read text such as `"1e-400"` as off, because `float()` rounds it to
  `0.0`, so the guard it sets would not have run. Now one reader, `float_setting` in
  `transports/base.py`, reads every float cap that `cap_setting` or `positive_cap` reads, and
  `poll_seconds`. It also reads at least these former bare `float()` reads: `timeout_seconds` and
  `connect_timeout` on the MLLP, TCP, X12 and DICOM connections, `timeout_seconds` on the FHIR, FHIR
  lookup, REST, SOAP, DICOMweb, Email and Direct connections, `acquire_timeout` on the DATABASE
  connections, the DATABASE lookup and a DATABASE reference source, the REMOTEFILE `connect_timeout`,
  the File source's `min_age_seconds`, the Timer source's `interval_seconds`, the HTTP source's
  `reply_timeout` and `reply_write_timeout`, and the OAuth2 and SMART token timeouts and expiry skews.
  Each refusal names the key and withholds the value. A float cap is off only for an exact zero, such
  as `0`, `"0"` or `"0.0"`; `"0e0"` is refused, as it already was on an integer cap. A
  `connections.toml` literal `1e-400` still reads as zero, because the TOML parser turns it into
  `0.0` before any reader sees it. The HTTP `reply_timeout` and `reply_write_timeout` now refuse
  zero, as `docs/CONNECTIONS.md` already said; a numeric `0` used to take the 30-second default.
  The `Http` factory's own check of those two keys refuses a bool, a NaN and an infinity too. The
  other timeouts above are checked for type only: a zero or negative `timeout_seconds`,
  `connect_timeout` or `acquire_timeout` is still not refused at build.
  At least the range refusals in `positive_cap`, `resolve_poll_ceiling` and `poll_interval`, the
  HTTP `max_header_bytes`, the File `max_decompressed_members` and the MLLP
  `max_connections_per_host` and `max_frame_seconds` checks now withhold the value too. The reader's
  docstring holds the full rule. (`BACKLOG #3432`)
