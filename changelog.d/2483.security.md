- **A generic-ODBC hop now needs a TLS mode, not just a TLS-named keyword.** Only `sslmode` or
  `encrypt` with a string value that is non-blank, has no blank at either end, and is off the no-TLS
  deny-list counts as the operator owning TLS on `dialect='generic'`. Any other TLS
  keyword alone, at least `sslkey`, `sslcert`, `sslca`, `sslcapath` or `sslcipher`, or a blank,
  padded or non-string mode, would have been read as ownership
  although a driver's own default need not require TLS. Such a hop now warns, is reported, and is
  refused off-loopback on an enforcing instance unless it declares `tls_hop_attested` or, outbound
  only, `cleartext_accepted`. `Encrypt=optional` is now on the no-TLS deny-list,
  since Microsoft documents it as a synonym for `no`. A mode value outside that list stays delegated. [CONNECTIONS.md](../docs/CONNECTIONS.md) records the limits of that, for `encrypt` and
  for psqlODBC's spelling of a mode. (`BACKLOG #2483`)
