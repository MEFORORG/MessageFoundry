- **`/ui/logout` audit rows for sign-outs that end no session are now bounded.** The route needs no
  credential, so any caller that could reach it could append `auth.logout` rows with `outcome`
  `nothing_to_revoke` without limit. For each engine process, each source now begins at most 3 such
  row writes in any 60 seconds, and all sources together at most 120, and the route writes at most
  one count row a window. A sign-out past either limit is counted, and only a sign-out that names no
  caller and ends nothing writes the count, in a row with `outcome` `unrecorded` and `"count": N`.
  The bound never stops the row of a sign-out that ends a session, or that names its caller as `POST
  /auth/logout` does. The bound is on the row, not the request: each request that passes the route's
  origin check (`assert_same_origin`) and carries a non-empty session cookie still runs a store
  write, the sign-out's revoke.
  [SECURITY.md](../docs/SECURITY.md#session-inventory--targeted-revocation-wp-10) states the bound
  and what the count can miss. (`BACKLOG #4735`, `BACKLOG #3749`)
