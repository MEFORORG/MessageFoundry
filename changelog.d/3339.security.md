- **A sign-out's `auth.logout` audit row records the client address it came from (ASVS 16.2.1).**
  Neither sign-out route passed an address, so on a first deployment an investigator could not
  have told from the audit log where a sign-out came from. `POST /auth/logout` and the console's
  `/ui/logout` now pass the same `client_ip` address the other audited auth routes record, and
  `AuthService.logout` takes it as a new optional `client` keyword. The row's actor is unchanged: the
  signed-in caller on `POST /auth/logout`, and the owner of the session it ended on `/ui/logout`. A
  console sign-out that ended nothing, including one that lost a rotation race, still names no
  actor, because the presented token no longer names a session. A sign-out that revokes nothing
  keeps its own recorded `detail.outcome`, `nothing_to_revoke`. The web console seam digest moved,
  so a console and engine built on either side of this change refuse each other at mount.
  (`BACKLOG #3339`)
