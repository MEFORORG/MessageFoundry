- **A sign-out's `auth.logout` audit row records the client address it came from (ASVS 16.2.1).**
  Neither sign-out route passed an address. On a first deployment, an investigator could not have
  told from the audit log where a sign-out came from. `POST /auth/logout` and the console's
  `/ui/logout` now pass the `client_ip` address, the extractor other audited auth routes use.
  `AuthService.logout` takes it as a required `client` keyword, so a new caller cannot omit it.
  A console sign-out now reads the session's owner before it revokes. A rotation that re-keys the
  session in between no longer leaves the row with no actor. A cookie that named no live session
  at that read still gives a row with no actor. A sign-out that revokes nothing keeps its own
  recorded `detail.outcome`, `nothing_to_revoke`. The web console seam digest moved, so a console
  and an engine built on either side of this change refuse each other at mount. (`BACKLOG #3339`)
