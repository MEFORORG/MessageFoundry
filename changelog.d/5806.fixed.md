- **The batch split drops the envelope trailer lines that end a message.** A `BTS`, `FTS`, `BHS`
  or `FHS` line that ends an `MSH`-led message, followed right after the id by that message's own
  field separator, no longer reaches the Handler. Every other cut is the one the split made
  before. A one-message file that a whole-file source hands over as its own bytes loses those
  lines only under a charset that writes ASCII as itself; under any other charset it goes over
  whole, as before. The
  `one_message_bytes` docstring in `messagefoundry/parsing/split.py` names those charsets.
  (`BACKLOG #5806`)
- **The dry run splits where byte order marks lead a later `MSH`**, as the live split of a UTF-8
  decode does. (`BACKLOG #5918`)
- **The base64 content sniff reads only the prefix it decodes**, and a character outside the
  base64 alphabet in that prefix now gives no signature. (`BACKLOG #5805`)
