- **Approving a held action needs a fresh step-up.** `POST /approvals/{id}/approve` and the
  console's approve now ask for a fresh step-up window, as the resolve already did, because the
  release runs the held operation. A JSON client that approved under a paced session gets **403**
  with `X-Step-Up-Required` until it re-authenticates. Reject still runs nothing and stays paced.
  For a held config reload, the release is still bound to the digest its approval named. (vault
  `BACKLOG #3241`)
- **Edit-resend gives back its proof when the engine refuses before it writes.** A refusal raised
  before the message-store write, such as a bad target or a guard rejection, returns the action
  proof, so the operator can submit again with no new password. A refusal at or after the store
  write keeps the spend. Export and edit-resend now check their own input before they spend the
  proof, so a malformed request costs no proof. (vault `BACKLOG #3241`)
- **The console mints an unlock page's grant only for a page it issued.** A re-auth toward a
  confirm page or the editor mints the action-bound grant only when a step-up gate issued that page
  to the session, once. A crafted `/ui/reauth?next=<page>` mints nothing and ends on the page saying
  nothing ran. `/ui/messages/{id}/resend-done` now needs `key` and renders from the store's record
  of that resend, so an old link carrying only `to` and `source` answers **422**. (vault
  `BACKLOG #3241`)
