- **The `[x12]` extra now needs pyx12 4.1.0, upstream's security release.** Under pyx12 4.0.1 a
  997/999 ack copied the ack's own separators (`~ * : ^`) as they came in the sender values it
  echoed, so a hostile value holding them could forge ack structure, and pyx12's error records
  carried the offending data value. 4.0.1 already wrote `?` for non-ASCII in an echoed bad value
  (AK404/IK404), but not in an echoed sender ID. 4.1.0 writes `?` for the ack separators, control
  characters and non-ASCII in most values it echoes, and cuts an echoed bad value at 99 characters,
  so an ack can differ from the sender's text in more places, sender and receiver IDs included.
  Its error-handler records carry no data value unless `log_data_values` is on, which the engine
  does not set and a pyx12 config file can.
  4.1.0 does not close either class. At least these remain: a 997 copies the sender's ISA11 as-is;
  a 997 splits an `*` in an echoed GS06 into extra AK1 elements, and both writers split one in an
  echoed segment ID; and other pyx12 records can still carry input text, such as the exception it
  logs when its ack writer fails. The engine's own guards are narrower than that: it reads the ack
  type from pyx12's report rather than the ack text, returns no ack whose last write was not its
  IEA, and mutes the `pyx12` logger tree, which stays the control on what pyx12 logs. Hostile input
  whose element value holds one of the ack writer's delimiters ends as a returned validation result,
  not an uncaught error.
- **Long X12 segments read differently.** pyx12 4.0.1 stopped reading at a segment whose terminator
  was neither in what it had buffered nor in its next 8 KB read, so a segment longer than 8 KB could
  end the read, and one longer than about 16 KB always did. `validate()` then returned `valid=False` with interchange
  error `023` (pyx12's `ISA_023_premature_eof`), and that segment and everything after it went
  unvalidated. 4.1.0 reads it whole, and `validate()` raises `X12ValidationError` for a segment
  with no terminator within 1 MiB, so such input gets no result and no ack.
