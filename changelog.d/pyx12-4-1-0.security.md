- **The `[x12]` extra now needs pyx12 4.1.0, upstream's security release.** Under pyx12 4.0.1 a
  997/999 ack copied sender values as they came, so a hostile value holding the ack's own
  separators could forge an ack segment, and pyx12's log records carried the offending data value.
  4.1.0 writes `?` for the segment terminator in the values it echoes, logs no data value unless
  asked to, and writes `?` for the other ack separators in most echoed values. Its 997 writer still
  splits an `*` in an echoed GS06 into extra AK1 elements. The engine's own guards stay: it reads
  the ack type from the validation report rather than the ack text, returns no ack whose last write
  was not its IEA, and mutes the `pyx12` logger tree. Hostile input whose element value holds one of
  the ack writer's delimiters ends as a returned validation result, not an uncaught error.
