- **A DATABASE source refuses a `poll_statement` that could write.** The poll runs on an
  autocommit connection, so a claiming poll such as `UPDATE ... RETURNING` would mark rows it never
  hands off: those past `poll_max_rows`, and those behind a failed hand-off or a stop. A statement
  that fails the `db_lookup` read-only test is now refused, a literal one when `DatabasePoll` is
  declared and every one when the source is built, whatever `poll_max_rows` is. At least a write
  keyword, `EXEC` or `{CALL ...}`, a second statement and a locking `FOR UPDATE` read are refused.
  Poll with a `SELECT` and mark rows with `mark_statement`. With no `mark_statement`, a full
  ceiling now logs a WARNING once per run of full polls instead of the "deferred" line. See
  [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #2178`)
