- **The dialling CA check of a lane reads the CA once per check, and a repeat of its last clean
  pass is not judged again.** It read the file, its ACL and its path twice, so on Windows each
  check ran `icacls` twice, and what it remembered could come from another read than the one it
  judged. A clean pass, one whose ACL reads as owner-only and whose path no other account can
  replace it through, is now remembered once its rows are written. A repeat skips the content
  check (the private-key and encryption-header refusal) and the audit pass only for the same
  setting, bytes, pin result and path findings, with the ACL read again found owner-only (the
  result of that read is compared, not the ACL itself), while the audited baseline still names
  those bytes. It still reads that baseline. A pass that wrote an `acl_insecure`,
  `acl_indeterminate`, `path_insecure` or `path_indeterminate` row, which a lane CA passes with
  only under `warn`, is never remembered: every check writes that row again and logs its
  warning, as before. A reload that removes or renames a lane now drops that lane's refusal
  mark and the check's memory of it. (`BACKLOG #3188`)
