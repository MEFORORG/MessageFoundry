- **An unreadable CA file is the named refusal on the arms that loaded it themselves.** The SMTP
  context's `tls_verify=false` arm (Email, Direct and the alerts sink), the DICOM C-STORE SCU
  context built with no `[tls]` policy, and the MLLP destination and FTPS contexts built with no
  policy or with `tls_verify=false` raised a bare `FileNotFoundError` for a missing file, and a
  raw `ssl.SSLError` for one with no usable PEM, naming nothing. They now raise
  `CaFileUnreadable`, naming the setting and, where there is one, the connection, and not the
  path, as the arms with a policy already did. A CA file that loads is trusted as before.
  (`BACKLOG #2370`)
