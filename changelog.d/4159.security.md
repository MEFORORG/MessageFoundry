- **A start now refuses a CRL that the CA it names by key identifier proves badly signed, even
  beside a CA of the same name that has no subject key identifier and cannot be checked.** Before,
  that second CA made the signature check read "cannot check", so the start loaded the file with a
  WARNING. Such a CA cannot make the CRL valid at a handshake: every verifying context the engine
  builds uses strict verification, and OpenSSL 3 refuses a chain through a CA with no subject key
  identifier. A CA the CRL names that cannot be checked still warns, and so does a lone CA with no
  subject key identifier that cannot be checked. The running-hop reload is unchanged. An OpenSSL
  build without that strict check could take such a CA for the CRL's issuer; the engine sets no
  OpenSSL version floor. (vault BACKLOG #4159)
