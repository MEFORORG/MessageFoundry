- **A port in an `[egress].allowed_db` entry binds the port a generic ODBC connection dials.** The
  check read the `port` setting on both dialects, but the generic dialect never sends it: the driver
  gets the `PORT` keyword in `odbc_params`. So an entry pinned to one port admitted a generic hop to
  another port on the same host, and refused the documented `PORT` shape on the pinned port. On the
  generic dialect the check now reads `PORT` alone, and ignores `port`. It refuses a listed
  `server` that carries a port, `PORT` given twice, and a pinned entry when no port can be read.
  The SQL Server preset reads `port` as before, now as a number. See [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #2704`)
