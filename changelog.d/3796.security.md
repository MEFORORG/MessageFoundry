- **A FHIR update reply that repeats a JSON key is compared as JSON values, at every occurrence.**
  An occurrence of a repeated key that itself reads two ways, at any depth below it, now fails
  closed as `reply-repeats-a-key`, as does `1` against `true`, `1` against `1.0` or `0.0` against
  `-0.0` in an occurrence or in a value the two readings are compared on. Before, a middle
  `response` that read `404 Not Found` only keeping the last key was delivered. Every `NaN` token
  now reads as one value, so a `NaN` beside a repeat no longer refuses. The compare is linear in
  the reply's size and does not recurse. See
  [ADR 0095](../docs/adr/0095-connection-lifecycle-scheduler-and-credential-fault-stop.md),
  Amendment B.1, the 2026-10-17 entry. (vault `BACKLOG #3796`)
