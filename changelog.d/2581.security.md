- **`POST /dr/activate` and `POST /dr/release` ask for step-up.** Both sat behind `require_paced`,
  while the planned failover on `POST /cluster/stepdown` asked for a fresh credential proof. They now
  use `require_step_up`, so a session outside its step-up window, or one calling from a new client
  address, is refused with `403` and `X-Step-Up-Required: 1`. A client that scripts a DR promotion
  calls `POST /me/reauth` first. See the route map in [SECURITY.md](../docs/SECURITY.md) and the
  amendment in [ADR 0048](../docs/adr/0048-third-tier-disaster-recovery-standby.md).
  ([BACKLOG #2581](../docs/BACKLOG.md))
- **`POST /config/reload` refuses a path outside the allowed roots before it touches the path.** The
  engine resolved `config_dir` first and compared second, and resolving a path opens it and each
  parent. The path is now compared with the roots as text, with no filesystem call on it, then
  resolved and compared again. A device-namespace path is always refused. A network share is refused
  unless it lies under a root that is itself that share. A subdirectory of a root still reloads. The
  resolve also moved off the event loop. Name the path the way the root is configured: another
  spelling of the same directory is refused. See `[api].config_reload_roots` in
  [CONFIGURATION.md](../docs/CONFIGURATION.md). ([BACKLOG #2581](../docs/BACKLOG.md))
- **An archive named in a `POST /dr/activate` request is confined to the new `[dr].seed_dir`.** The
  path was unconfined. A request may now name only an archive under `seed_dir`, and none while that
  key is empty, which is the default. The same text-first check applies, and a refusal answers `422`
  with one generic message that names no part of the path. `[dr].seed_archive` is unchanged. A
  runbook that passes the archive in the request body must set `[dr].seed_dir`. See `[dr]` in
  [CONFIGURATION.md](../docs/CONFIGURATION.md). ([BACKLOG #2581](../docs/BACKLOG.md))
