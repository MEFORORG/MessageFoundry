- **A self-signed certificate the engine mints for a wildcard `serve --host` bind names the
  loopback the tray dials.** A pair minted for a `0.0.0.0` or `::` bind also names the loopback of
  its family, the address the tray dials for that bind, so the tray's pinned probe verifies it. An
  operator certificate on a wildcard bind must name that loopback too. (`BACKLOG #5973`)
- **A generated pair that does not name the current bind is re-minted at the next start.** When
  the engine reuses the self-signed pair it generated, and that certificate does not name the
  address a client dials for the current bind, for example after the bind moved from `0.0.0.0` to
  `::`, the engine replaces the pair with one for that bind, rather than serving the old one until
  its renewal. A bracketed `[::1]` bind is named by the address `::1`. A key replace that fails
  after the certificate replace puts the old certificate back, so the previous pair is on disk
  again and the start can serve it. The replacement is audited with reason `bind_changed`, and the
  new certificate must be imported again; docs/SERVICE.md states the rule. An operator
  `[api].tls_cert_file` is never touched. Known limit: the tray does not read the bind from the
  engine's settings TOML, so a bind set only through `[security].listen_address` or `[api].port`
  is not discovered; set it with `serve --host` and `--port`, which `install-service.ps1` always
  writes. (`BACKLOG #5973`)
