- **`validate`, `graph` and `dryrun` evaluate the environment `--env` names.** They used the flag
  only for the value-file check under `--project-root`, and without `--project-root` it had no
  effect, so a gate given `--env prod` could exit 0 on a graph `serve --env prod` refuses. Given
  `--env`, they now read that environment's values with `serve`'s reader: the value file under
  `--project-root`, else under the working directory, plus `MEFOR_VALUE_*`. Each `env()` reference
  of a deployed connection or lookup that does not resolve is reported by its key, never its value:
  `validate` lists it with its other problems, and `graph` and `dryrun` exit with it. A value file
  that cannot be read, or a `--service-config` that names no file, fails the command; an absent
  value file reads as no values, with a note naming it. With no `--env`, nothing changes. They
  build no connector, so the build and posture checks stay `check --env`'s. ADR 0050 records where
  they still differ from `serve`. (`BACKLOG #5554`)
