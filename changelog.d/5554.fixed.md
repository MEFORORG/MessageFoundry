- **`validate`, `graph` and `dryrun` evaluate the environment `--env` names.** They used the flag
  only for the value-file check under `--project-root`, and without `--project-root` it had no
  effect, so a gate given `--env prod` could exit 0 on a graph whose `env()` values `serve --env
  prod` cannot resolve. Given `--env`, they now find and read that environment's values as `serve`
  does: the service settings load `serve` runs, with `--project-root` overriding
  `[environments].base_dir`, then `serve`'s value reader, so overrides such as `MEFOR_VALUE_*`
  apply. Each `env()` reference of a deployed connection or lookup that does not resolve is
  reported by its key, never its value: `validate` lists it with its other problems, and `graph`
  and `dryrun` exit with it. Settings that do not load, or a value file that cannot be read, fail
  the command; an absent value file reads as no values, with a note naming it. With no `--env`,
  nothing changes. They build no connector, so the build and posture checks stay `check --env`'s.
  ADR 0050 records where they still differ from `serve`. (`BACKLOG #5554`)
