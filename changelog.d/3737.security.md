- **`rotate-key` keeps a rotation record, and a `serve` start does not stamp a key while that
  record names it.** The command opens the record in `secret_rotation_meta` inside its store
  open, before that open's first write under the key (`BACKLOG #4936`). It opens none when the
  store-key stamp already names the key the run moves to. A record already open for another key
  is replaced, keeping its dates. The command closes the record only when a run gets through both
  data passes with no upload skipped and its audit roll does not refuse; a run on the key already
  in use closes an open record too. So a run that stops short of that leaves an open record open,
  and so does one killed inside the store open after the record opened. A run killed before that point
  opens no record and leaves any record an earlier run opened as it was. When a start finds that
  the key in use differs from its stamp, has none, or has one under a scheme this release does not
  know, and the record names that key or cannot be read, `serve` writes no stamp, does not reset
  the key's age, and logs a WARNING. On a store with a keyed audit chain, a start also holds such a
  key at least where the open does not find the chain rolled to it, and opens the record for it
  if none is open, and where a record stands open for another key, which it keeps. On a store with
  no keyed audit chain, a record naming another key holds nothing, and the start stamps the key.
  The `BACKLOG #4942` entry says more. **Once a run
  has rolled a keyed audit chain to a new key there is no way back to the prior key**, and a run that skipped an uploaded file rolls like any other. **The upload
  pass opens only a regular file, and reads whole only one of a size an upload can be.** A FIFO no
  longer blocks it, a symlink is a skip and is not followed, and a file too large for an upload is a
  skip rather than an abort, unless it starts with the active key's marker, which reads as already
  current. Its log now says whether the key a skipped value names is configured. See
  [PHI.md](../docs/PHI.md). (`BACKLOG #3737`)
