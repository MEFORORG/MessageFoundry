- **`rotate-key` keeps a rotation record, so a `serve` start no longer stamps a key while a run on
  it stands unfinished.** The command opens the record in `secret_rotation_meta` before either data
  pass and closes it only when a run completes. While the record names the key in use, or cannot be
  read, `serve` writes no stamp, does not reset the key's age, and logs a WARNING. A key changed with
  no record still stamps, including a start that comes before the first run, so a stamp does not
  prove a rotation finished. **There is no way back to the prior key after any run reaches the audit
  step**, one that skipped an uploaded file included, because a key opens one audit range. Recovery
  is to fix the cause and re-run, or to rotate to a new key. **The upload pass opens
  only a regular file of a size an upload can be.** A FIFO no longer blocks it, a symlink is a skip
  and is not followed, and a huge file is a skip rather than an abort. Its log now says whether the
  key a skipped value names is configured. See [PHI.md](../docs/PHI.md). (`BACKLOG #3737`)
