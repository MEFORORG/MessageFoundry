- **`rotate-key` keeps a rotation record, so a `serve` start no longer stamps a key while a run on
  it stands unfinished.** The command opens the record in `secret_rotation_meta` before either data
  pass and closes it only when a run completes. When a start finds that the key in use differs from
  its stamp, or has none, and the record names that key or cannot be read, `serve` writes no stamp,
  does not reset the key's age, and logs a WARNING. A key changed with
  no record still stamps, including a start that comes before the first run, so a stamp does not
  prove a rotation finished. **Once a run has rolled a keyed audit chain to a new key there is no way
  back to the prior key**, and a run that skipped an uploaded file rolls like any other. **The upload
  pass opens only a regular file, and reads whole only one of a size an upload can be.** A FIFO no
  longer blocks it, a symlink is a skip and is not followed, and a file too large for an upload is a
  skip rather than an abort, unless it starts with the active key's marker, which reads as already
  current. Its log now says whether the key a skipped value names is configured. See
  [PHI.md](../docs/PHI.md). (`BACKLOG #3737`)
