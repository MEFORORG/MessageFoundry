- **`rotate-key` keeps a rotation record, so a `serve` start no longer stamps a key once a run on
  it has opened that record and not finished.** The command opens the record in
  `secret_rotation_meta` before either data pass, after its store open, and closes it only when a
  run completes. When a start finds that the key in use differs from its stamp, or has none, and the
  record names that key or cannot be read, `serve` writes no stamp, does not reset the key's age,
  and logs a WARNING. A run killed inside the store open, before the record opens, leaves no
  record. On a store with a keyed audit chain, a start that then finds the key changed opens one
  itself, as does a start before the first run; the `BACKLOG #4942` entry says when. **Once a run
  has rolled a keyed audit chain to a new key there is no way back to the prior key**, and a run that skipped an uploaded file rolls like any other. **The upload
  pass opens only a regular file, and reads whole only one of a size an upload can be.** A FIFO no
  longer blocks it, a symlink is a skip and is not followed, and a file too large for an upload is a
  skip rather than an abort, unless it starts with the active key's marker, which reads as already
  current. Its log now says whether the key a skipped value names is configured. See
  [PHI.md](../docs/PHI.md). (`BACKLOG #3737`)
