- **The mTLS issuer index reads a CA written under the legacy `X509 CERTIFICATE` PEM label, and
  no longer reads a certificate OpenSSL skipped inside another block.** The index names the loaded
  CA that issued a client certificate, for at least `[api].tls_client_cert_identities`, an inbound
  `Http` listener's `intake_client_subjects` and an inbound MLLP listener's `tls_client_subjects`.
  The TLS library loads the legacy label from the CA file each of them reads, so the handshake
  verified a client under such a CA, but the index read only `BEGIN CERTIFICATE` blocks. On a
  first deployment every client under that CA would have been refused, and the start warning would
  have said the issuer key named no loaded CA. A second CA with the same DN and a different key
  under the legacy label would have been missed too, so a client under the other one would have
  been admitted although the two cannot be told apart; both are now refused, as with the standard
  label. The index also read a `CERTIFICATE` block nested inside a
  block of another label, such as a CRL, which OpenSSL skips whole. A client that sent that nested
  CA as its intermediate would have verified through a CA OpenSSL did load, and would have been
  named under the nested CA, so a subject listed under it would have been admitted. The index now
  skips the body of a block whose label is not a certificate's, where OpenSSL skips it. A BEGIN
  marker counts only where it opens a line and fills it, as OpenSSL was measured to read one, so on
  the shapes the tests sample a comment naming a marker neither hides the blocks after it nor names
  a block OpenSSL skipped. The index models OpenSSL's reader rather than asking it, so this is not
  a promise for every layout a file could take. **At least one known shape still names a CA the
  context never loaded:** OpenSSL silently stops loading a file at a block of any label whose body
  decodes to no data, such as an empty block, while the index reads on and names the CAs after it.
  This repair does not change that. A certificate block is parsed from the lines as OpenSSL read
  them, so trailing control bytes OpenSSL strips from a marker line, or a base64 line wrapped at
  OpenSSL's 254-byte read size, no longer leave its CA unreadable. A block under either label
  that `cryptography` cannot parse, including a certificate with an unknown version, is counted,
  and the start warning that it could not be parsed fires. A CA with an unknown version raised out
  of the context build in the shipped code, and the issuer lookup now names no issuer for a client
  leaf with one rather than raising.
