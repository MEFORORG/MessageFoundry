- **A client CA written under the legacy `BEGIN X509 CERTIFICATE` PEM label now names its
  partners.** The TLS context loads such a block, so the handshake verified a leaf under that CA,
  but the issuer index behind `intake_client_subjects` on the HTTP listener and
  `[api].tls_client_cert_identities` on the API read only `BEGIN CERTIFICATE` blocks. Every
  partner under that CA would have been refused, and the start warning said the key named no
  loaded CA rather than that a block went unread. The index now reads the two labels the context
  loads, only from a BEGIN line that is the marker alone, and checks what it read against a TLS
  context loaded from the same text. A certificate OpenSSL counts as a CA is named only where that
  context holds it, and one the scan missed is taken from there; a certificate it does not count as
  a CA is kept only where the two agree on how many there are. A certificate set aside names no
  issuer, and a new start warning counts it. A block under either label that cannot be parsed
  still names no issuer and is still counted in the start warning. (vault BACKLOG #4948)
