- **The mTLS issuer index reads a CA written under the legacy `X509 CERTIFICATE` PEM label.** The
  TLS library loads that label from `[api].tls_client_ca_file` and an inbound `Http` listener's
  `tls_ca_file`, so the handshake verified a client under such a CA, but the index that names the
  issuing CA read only `BEGIN CERTIFICATE` blocks. On a first deployment every client under that
  CA would have been refused, under `[api].tls_client_cert_identities` and under
  `intake_client_subjects`, and the start warning would have said the issuer key named no loaded
  CA. A second CA with the same DN and a different key under the legacy label was missed too, so
  a client under the other one was admitted although the two cannot be told apart; both are now
  refused, as with the standard label. A block under either label that `cryptography` cannot
  parse, including a certificate with an unknown version, is counted, and the start warning that
  it could not be parsed fires. A CA with an unknown version had raised out of the context build,
  and the issuer lookup now names no issuer for a client leaf with one rather than raising.
  (`BACKLOG #4948`)
