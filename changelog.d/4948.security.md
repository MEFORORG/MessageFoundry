- **A client CA written under the legacy `BEGIN X509 CERTIFICATE` PEM label now names its
  partners.** The TLS context loads such a block, so the handshake verified a leaf under that CA,
  but the issuer index behind `intake_client_subjects` on the HTTP listener and
  `[api].tls_client_cert_identities` on the API read only `BEGIN CERTIFICATE` blocks. Every
  partner under that CA would have been refused, and the start warning said the key named no
  loaded CA rather than that a block went unread. The index now reads the two labels the context
  loads, and only from a BEGIN line that is the marker alone, as the context reads one, measured
  shape by shape against OpenSSL. So at least these shapes the context skips are no longer read as
  a CA: a marker after other text on its line, and a marker followed by text, as in a comment line.
  The index models OpenSSL's reader rather than being it; in the one disagreement measured, a
  marker 254 bytes into a long line, the CA is left out, which denies rather than admits. A block
  under either label that cannot be parsed still names no issuer and is still counted in the start
  warning. (vault BACKLOG #4948)
