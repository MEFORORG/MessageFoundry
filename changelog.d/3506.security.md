- **The CRL signature check at start keeps a proof it has reached, and the reload warns before a
  restart that would fail.** A `bad_signature` refusal for a CRL file not yet in effect now carries
  `start_refuses`, as a `restart` refusal does. For every class, the reload's reason and the
  alert now say a start refuses such a file "at least until" its CRL takes effect: a start can
  still refuse it after then, as it does a proven bad signature.
  If the check fails part way through a file, a CRL it already proved badly signed
  still refuses the start, beside the ERROR; before, the whole judgment was dropped and that CRL
  loaded. A listed CA whose serial number is not positive, as at least some system roots have, is
  now read and judged by the signature check like any other CA, with no `cryptography` warning,
  including one that names that serial again in its own authority key identifier; where warnings
  are errors, that warning used to end the check, and later made the check skip that CA. The
  issuer name the signature check quotes is bounded: its quoted form, escapes included, holds at
  most 200 characters, and a note of the name's full length follows a cut one. The
  0.5.2 entry said a start refuses a CRL whose named key "did not sign it": it refuses only where
  the engine ran the check with that key and it failed, so a signature of another kind than the
  key loads with a WARNING. (vault BACKLOG #3506)
