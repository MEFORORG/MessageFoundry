- **Three more routes from a codec error to a log line are closed, within the attribute
  budget.** An exception whose own
  `__str__` or `__repr__` printed a dunder-named slot, an attribute of a plain exception it held,
  or any link of its `__cause__` and `__context__` chain would have printed the character or byte
  a codec could not handle, which can be message content. The walk now follows that whole chain
  and reads at least the instance `__dict__`, the slots and the chain links of each exception
  beneath such a method. Those reads run after every read the walk made before, on only the work
  budget those left, and only add, so an error the earlier reads found still gets the fixed note;
  past that budget an error only they would reach prints raw. Such an exception now prints as its class and a fixed note in a
  traceback, as a log argument and in `safe_exc()`. One whose `__str__` or `__repr__` is not a
  builtin exception's therefore loses its message whenever it is raised from a codec error or
  while one is being handled: at least one written in Python, a dataclass exception's generated
  `__repr__`, and a C extension's such as `ssl.SSLError`'s. A builtin exception raised from a
  codec error keeps its message, since a builtin `__str__` never prints the chain. One that stores
  an error on an attribute keeps its message only when its `__str__` and `__repr__` are
  `BaseException`'s own; at least `OSError` and `KeyError` define their own, and get the fixed
  note. A `UnicodeError`'s own traceback prints only the note a codec adds itself, naming the
  codec only when the error line would. A note a caller added is still dropped, plain text
  included, since it can be built from the failing input. (`BACKLOG #3340`)
