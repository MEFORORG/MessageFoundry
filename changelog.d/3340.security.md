- **Three more routes from a codec error to a log line are closed.** An exception whose own
  `__str__` or `__repr__` printed a dunder-named slot, an attribute of a plain exception it held,
  or any link of its `__cause__` and `__context__` chain would have printed the character or byte
  a codec could not handle, which can be message content. The walk now follows that whole chain
  and reads at least the instance `__dict__`, the slots and the chain links of each exception
  beneath such a method, within the same work budget as before. Such an exception now prints as its class and a fixed
  note in a traceback, as a log argument and in `safe_exc()`. One whose `__str__` or `__repr__`
  is not a builtin exception's therefore loses its message whenever it is raised from a codec
  error or while one is being handled: at least one written in Python, a dataclass exception's
  generated `__repr__`, and a C extension's such as `ssl.SSLError`'s. A builtin exception, and one
  whose `__str__` and `__repr__` are `BaseException`'s own, keeps its message. Every
  `UnicodeError`'s own traceback again prints the plain-text notes it holds itself, which the
  earlier fix had dropped with every other note. The stdlib's codec note names the codec only
  when the error line would, and the note the stdlib writes when `__notes__` cannot be read is
  dropped, since it can carry an error's whole input. (`BACKLOG #3340`)
