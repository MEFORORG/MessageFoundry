- **Three more routes from a codec error to a log line are closed, within the attribute budget.**
  An exception whose own `__str__` or `__repr__` printed a dunder-named slot, an attribute of a
  plain exception it held, or a link of its `__cause__` and `__context__` chain would have printed
  a codec error, whose text names the character or byte the codec could not handle and whose
  `repr()` carries the whole input, either of which can be message content. The walk now reads
  those too, after the reads it made before and on what budget those left, plus in a traceback one
  more budget all its links share, with one link's verdict handed on to a later link, so an error
  the earlier reads found still gets the fixed note. An exception's instance `__dict__` is now read
  through the builtin descriptor even where its class puts something else under that name, so an
  error held there that was skipped or withheld before now gets the note. Past the budget, an error only the new reads would reach
  still prints raw. An exception found holding one prints as its class and a fixed note in a
  traceback, as a log argument and in `safe_exc()`, so one whose `__str__` or `__repr__` is not a
  builtin exception's can lose its message when it is raised from a codec error or while one is
  being handled. Of a `UnicodeError`'s own notes, its traceback keeps only one that reads exactly
  like the note a codec adds itself, naming the codec only when its name is one `safe_exc()` can
  print; any other note is dropped, plain text included, since a caller can build one from the
  failing input. (`BACKLOG #3340`)
