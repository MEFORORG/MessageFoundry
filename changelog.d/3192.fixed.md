- **`GET /approvals` names a release the gate always refuses.** Each pending request carries
  `release_blocked`: `no_requester_id`, `operation_unavailable`, `not_gated`,
  `params_unreadable` or `params_no_requester`, read from the same tests the release refuses on,
  or `null`. The web console uses it to stop offering Approve on such a row. A release refused
  because its stored parameters are unreadable now writes an `approval.params_unreadable` audit
  row against the approver, like the gate's other refusals. A held purge or reload whose
  parameters name no requester is refused before the claim, as `params_no_requester`, with an
  `approval.params_no_requester` row, so it stays pending for a reject. (vault `BACKLOG #3192`)
