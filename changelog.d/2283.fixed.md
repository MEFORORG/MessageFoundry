- **Session follow-ups from the session-cap work.** The session reaper now takes a clock reading at
  start and runs its first pass five minutes later, then hourly. It skips any pass after which the
  wall clock has run more than ten minutes ahead of the monotonic clock, so a forward clock step no
  longer purges the sessions nobody used during it; the next pass purges if the clock holds. A
  session that is presented during the step is still refused and revoked. The session inventory
  now lists a session at the instant it expires, as the validator still accepts it. An AD group-map
  edit now revokes every unrevoked directory session, including rows the clock calls expired, which
  could otherwise come back on the old mapping. Revoking a user's sessions (sign out everywhere,
  disable, password reset, role change) and session rotation now report what they changed reliably
  on SQL Server, from an `OUTPUT` rowset that a session-wide `SET NOCOUNT ON` cannot hide. On
  Postgres both borrow a pooled connection under `[store].acquire_timeout`, so a saturated pool
  fails them after that timeout instead of waiting without limit. (`BACKLOG #2283`)
