- **Session follow-ups from the session-cap work.** The session reaper now takes a clock reading at
  start and runs its first pass five minutes later, then hourly. It skips any pass after which the
  wall clock has run ahead of the monotonic clock by more than half the idle window, and never more
  than ten minutes, so a forward clock step no longer purges the sessions nobody used during it; the
  next pass purges if the clock holds. A
  session that is presented during the step is still refused and revoked. The session inventory
  now lists a session at the instant it expires, as the validator still accepts it. An AD group-map
  edit now revokes every unrevoked session of an enabled directory account, including rows the clock
  calls expired, which
  could otherwise come back on the old mapping. Revoking a user's sessions (sign out everywhere,
  disable, password reset, role change) and session rotation now report what they changed reliably
  on SQL Server, from an `OUTPUT` rowset that a session-wide `SET NOCOUNT ON` cannot hide. On
  Postgres both still wait for a free pooled connection without `[store].acquire_timeout`, because
  each follows a change its caller has already committed. A sign-in or a completed second factor
  that pushes a user over `[auth].max_sessions_per_user` now writes an `auth.session_revoked` audit
  row with scope `cap` and the number of sessions it ended, under that user's name; before, the cap
  revoked sessions with no audit row. (`BACKLOG #2283`)
