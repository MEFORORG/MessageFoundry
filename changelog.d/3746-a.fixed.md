- **A store fault in a trust-anchor check no longer reads as a refused anchor or a failed build.**
  An inbound start or restart the store stopped answers 503 rather than the 409 of a refused CA,
  and a restart's answer says it left the connection stopped. A connection test reports one fixed
  store line, not "connector build failed". A refused start's `connection_control` row is now
  fail-soft, so a store that also refuses that row leaves the answer standing rather than a 500.
  An audit page ending in a row whose `ts` is not a finite number is the same store fault, not a
  `ValueError`. `refused_connection_anchor` is now `connection_anchor_failure`, since it also
  answers a store fault. See [SECURITY.md](../docs/SECURITY.md). (`BACKLOG #3746`)
