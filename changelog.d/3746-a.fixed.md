- **A store fault in a trust-anchor check no longer reads as a refused anchor or a failed build.**
  An inbound start or restart the store stopped answers 503 rather than the 409 of a refused CA,
  its `connection_control` row carries `reason` `store_unavailable`, and a restart's answer says it
  left the connection stopped. A connection test reports one fixed store line, not "connector build
  failed". Those two rows are fail-soft on that path, so a store that also refuses the row leaves
  the answer standing rather than a 500. So is a refused start's row for any other reason. The
  fingerprint look-back pages on `id`, so it reads no `ts`: a malformed one no longer raises
  `ValueError`, and a page all at one instant no longer reads as a first observation.
  `refused_connection_anchor` is now `connection_anchor_failure`, since it also answers a store
  fault. See [SECURITY.md](../docs/SECURITY.md). (`BACKLOG #3746`)
