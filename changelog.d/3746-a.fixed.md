- **A store fault in a trust-anchor check no longer reads as a refused anchor or a failed build.**
  A start or restart the store stopped answers 503, on an inbound rather than the 409 of a refused
  CA, and on an outbound rather than a 200. Its `connection_control` row carries `reason`
  `store_unavailable`, and a restart's answer says it left the connection stopped. An outbound with
  no connector stays paused with its rows pending, rather than resuming and charging each row an
  attempt. A connection test reports one fixed store line, not "connector build failed", and its row
  carries the same `reason`. Three rows are now fail-soft: that `connection_control` row, the same
  row for any refused inbound start, and the `connection_test` row of a test that ended at its CA
  check, whatever stopped it. A store that also refuses one leaves the answer standing rather than
  a 500. The fingerprint look-back pages on `id`, so it reads no `ts`: a malformed one no longer
  raises `ValueError`, and a page all at one instant no longer reads as a first observation.
  `refused_connection_anchor` is now `connection_anchor_failure`, since it also answers a store
  fault. See [SECURITY.md](../docs/SECURITY.md). (`BACKLOG #3746`)
