- **Each upload-quota reservation now has its own identity.** The cross-shard ledger holds one
  row per upload in flight, named by the upload's `file_id`, in a new `upload_reservation` table
  that replaces `upload_quota` on all three store backends. A leaked slot is reclaimed once its own
  window passes, however active the uploader stays; a release pays back only its own slot; and a
  reserve whose outcome is unknown is released by its id. A ledger call a cancelled upload left
  running is cancelled after `_LEDGER_STRAGGLER_MAX_SECONDS`, the engine drains what is left
  before it closes the store, and a cancelled upload's file is removed before the next upload in
  the same process scans the disk, so that upload is no longer refused at the quota edge.
  `Store.reserve_upload_quota` takes a `reservation_id` and no longer releases;
  `release_upload_quota` and `touch_upload_quota` are new. (vault `BACKLOG #3180`)
