- **Under `[security].enforcement = "enforce"`, `serve` and `supervise` now refuse an operator's
  own key file that a broad group can read.** That is `[api].tls_key_file`, or `[api].tls_cert_file`
  when the key is in the certificate PEM, beside the store key file and the generated TLS key they
  already checked. A connection's key file is graph data, so a registry guard checks it at each
  load, at the start and on every reload, with `env()` values resolved: at least `tls_key_file` on
  MLLP, the HTTP listener, DICOM and FTPS, and `Soap(client_key_file=...)`. A refused reload keeps
  the running graph, and `supervise` refuses such a graph before it starts an engine shard. Under
  `"warn"` each finding is a warning. See [PHI.md](../docs/PHI.md), *Key files*.
  (`BACKLOG #3402`)
