- **The audit rows an IdP step-up's return writes on its repeatable refusals have a ceiling
  across users.** A `state` mismatch on a step-up return, on the completion or the abandon leg,
  and a non-navigation fetch of `GET /ui/oidc/callback` consume nothing, so they repeat while the
  flow lives. Their rows were bounded only per user, so many users' flows could write about
  10 rows a window each. `AuthService.allow_step_up_return_audit` now draws a budget of its own,
  on the login knobs: 10 rows per user and 60 across all users a window. It gates the row only.
  Past it the refusal answers as before and writes a WARNING line instead, so a flood across many
  users cannot refuse anyone's step-up return. It never draws the sign-in window or the ceremony
  budget, and `[auth].login_rate_limit_enabled = false` removes it with them. (`BACKLOG #3965`)
