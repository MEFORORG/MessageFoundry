- **The subprocess sandbox narrows two forged-answer routes.** Under `[sandbox].mode` `subprocess`
  or `isolated`, the engine now checks again, right before it writes a request, for a frame the
  worker was not asked for, so a frame that arrives while the request is encoded costs that
  message a retry on a fresh worker instead of a failed call. The worker also moves its request
  pipe off fd 0 before it reads its boot frame, so a process a Handler starts with `subprocess`
  no longer inherits the pipe and cannot read a later request from it. Other routes to the pipe
  remain, at least a POSIX `fork` with no `exec` and the `/proc` and Windows routes; see
  [ADR 0087](../docs/adr/0087-sandbox-subprocess-isolation.md). (`BACKLOG #3135`)
