- **A `DatabaseRef` statement passes the `db_lookup` read-only statement test, and a row ceiling
  bounds each sync.** The statement must open with `SELECT` or `WITH`, carry no write, `EXEC` or DDL
  keyword, and chain no second statement, so a stored-procedure `DatabaseRef` is now refused. It is
  tested when declared, by the build check, and at every sync. The sync connection now advertises
  `ApplicationIntent=ReadOnly`; against an Always On listener with read-only routing it reads a
  readable secondary, and a primary set to `ALLOW_CONNECTIONS = READ_WRITE` refuses it. New
  `DatabaseRef(max_rows=…)`, default `100000` and `0` for off, refuses a larger result and keeps
  the last-good snapshot. Neither control is read-only authority: give the login `SELECT` only. See
  [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #2617`)
