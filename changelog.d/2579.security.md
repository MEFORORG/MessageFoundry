- **A loopback hop is never sent through a web proxy.** The engine allows a cleartext `http://`
  hop to a loopback host because that hop stays on the box. `urllib`'s proxy handler did not know
  that rule. With `HTTP_PROXY`, `HTTPS_PROXY` or the Windows system proxy set and no `NO_PROXY`
  entry, a request to `127.0.0.1` would have gone to the proxy. Every engine `urllib` opener now
  dials a loopback host direct: `127.0.0.0/8`, `::1` or the name `localhost`, decided without DNS
  by the same rule the cleartext check uses. That holds for a proxy from the environment, the
  system proxy and a configured `proxy_url` alike. It covers at least the HTTP family and its token
  endpoints, the alert webhook, the OIDC legs and the AI broker. An off-box hop still uses the
  proxy as before. A per-connection proxy resolved for a loopback destination now attaches no
  proxy handler and no `Proxy-Authorization` header. The ECH sidecar hop uses no proxy at all, and
  `ech_sidecar` is now read by the same loopback rule: a name that only starts with `127.`, and the
  short form `127.1`, are refused at build. Write the full address, such as `127.0.0.1`. See
  `[egress]` in [CONFIGURATION.md](../docs/CONFIGURATION.md) and Amendment B of
  [ADR 0126](../docs/adr/0126-outbound-forward-egress-web-proxy-for-the-stdlib-http-family.md).
