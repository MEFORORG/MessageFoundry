- **The hops built before the trust-anchor start check now take it first.** `serve` and
  `supervise` check `[logging].forward_tls_ca_file` before they build the log forwarder. A CA
  another account could replace, or one the engine cannot read, now builds no forwarder, so no
  record is sent. `serve` logs that forwarding is off, and its audited start check then refuses
  the start and writes its audit row. `supervise` did not check the CA before. It now refuses on
  stderr before any engine shard spawns. `serve` also checks the CA its alert email reads before
  it builds the alert notifier. That is `[alerts].email_tls_ca_file`, or the
  `[tls].internal_ca_file` it falls back to. A refused CA builds the notifier without email, so
  the webhook still pages startup alerts, and the audited start check then refuses the start. The
  offline recovery commands check the relay's CA too. A refusal there drops the security notice
  with a WARNING, and the recovery goes on. Under `[security].enforcement = warn` each check warns
  and goes on. (`BACKLOG #3470`)
