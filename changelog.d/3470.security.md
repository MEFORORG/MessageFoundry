- **The hops built before the trust-anchor start check now take it first.** `serve` and
  `supervise` check `[logging].forward_tls_ca_file` before they build the log forwarder, so a
  collector CA another account could replace, or one the engine cannot read, refuses the start
  before any record is sent. `supervise` checked it nowhere before. The refusal goes to stderr with
  no audit row, since no store is open yet. `serve` checks the CA the alert notifier's SMTP hop
  reads, `[alerts].email_tls_ca_file` or the `[tls].internal_ca_file` it falls back to, before it
  builds the notifier. A refused CA builds no notifier, so startup alerts go to the log, and the
  audited start check then refuses the start and writes its rows. The offline recovery commands
  check the relay's CA too; a refusal drops the security notice with a WARNING and the recovery
  goes on. Under `[security].enforcement = warn` each warns and goes on. Each hop still loads the
  file by path after its check. (`BACKLOG #3470`)
