- **The hops built before the trust-anchor start check now take it first.** `serve` and
  `supervise` check `[logging].forward_tls_ca_file` before they build the log forwarder. A CA
  another account could replace, or one the engine cannot read, now refuses the start before any
  record is sent. `supervise` did not check it before. The refusal goes to stderr with no audit
  row, since no store is open yet. `serve` also checks the CA its alert email reads before it
  builds the alert notifier. That is `[alerts].email_tls_ca_file`, or the `[tls].internal_ca_file`
  it falls back to. A refused CA builds no notifier, so startup alerts go to the log, and the
  audited start check then refuses the start. The offline recovery commands check the relay's CA
  too. A refusal there drops the security notice with a WARNING, and the recovery goes on. Under
  `[security].enforcement = warn` each check warns and goes on. (`BACKLOG #3470`)
