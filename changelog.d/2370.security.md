- **Per-connection `tls_ca_file` follow-ups.** A blank `env()` value for `tls_ca_file` is now
  refused when it resolves, naming the setting, the connection and the environment key. Before, it
  read as unset, so the hop would have trusted what it trusts with no pin. A CA file that cannot be
  read now raises `CaFileUnreadable`, which names the setting, the path and, where the build knows
  it, the connection. It is both a `ValueError` and an `OSError`; before, it was a bare
  `FileNotFoundError` naming only the path. The inbound FTPS poller now reads the instance `[tls]`
  block, as the FTPS upload does: `internal_ca_file` and `crl_file` reach it. The token hop still
  shares the data hop's `tls_ca_file`, as
  [CONNECTIONS.md](../docs/CONNECTIONS.md#pinning-a-private-ca-per-connection-tls_ca_file) says.
  (`BACKLOG #2370`)
