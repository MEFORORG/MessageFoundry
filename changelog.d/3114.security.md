- **A label spelled with a fold character as its first letter now stops a plain value.** Under a
  `MEFOR_*` label in the shipped log scrub, and under every label in the support bundle, a value ran
  on over a later quoted label whose keyword began with a character Python's case-insensitive
  matching reads as an ASCII letter (for example U+017F in `secret`), and would print that label's
  value. The value walk now checks for a label in front of such a character where it starts a word,
  as it does in front of a run of ASCII letters, and takes one inside a word as part of that word,
  unchecked. The run after it is still checked, as before, so a keyword glued on behind one, as in
  `b2<U+017F>token=`, stops a value where its ASCII spelling `b2stoken=` does not: a line holding a
  fold character does not in general read as its ASCII spelling. Because such a label now stops a
  value, it also takes part in the cascade shapes pinned as open defects in `secretscrub.py`: on
  those lines it prints, on every surface, values the previous code hid, the same ones its ASCII
  spelling prints. On the support bundle it can also print a value its ASCII spelling hides, where
  the line holds a label whose prefix a fold character heads, as in `<U+0130>_password=`, which the
  bundle copy does not read. The lines found are pinned; they are not a census. The support bundle
  keeps its own copy of the credential patterns: the shared pass alone has not been shown to print
  nothing the copy hides. (`BACKLOG #3114`)
