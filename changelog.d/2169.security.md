- **Behind an ECH sidecar, a CRL no longer lifts the revocation refusal on a SMART or OAuth2 token
  endpoint.** With `ech_sidecar` set, the engine sends the token request to the loopback sidecar,
  and the sidecar makes the TLS connection to the token host. The engine's own TLS context never
  meets that host. A `[tls].crl_file` that covered the token host still landed on that context,
  and the revocation check read it as proof. On a first deployment under an enforcing posture, an
  off-loopback token endpoint would have crossed with no revocation check behind it. The check
  now ignores that context when a sidecar is set. The hop is refused unless the connection sets
  `tls_revocation_attested = true` with a `tls_revocation_attested_reason`, and the refusal names
  that attestation alone. A token endpoint with no sidecar is unchanged: a CRL that reaches it
  still lifts the refusal. The decision is the note dated 2026-10-04 in section 4.3 of
  [ADR 0173](../docs/adr/0173-tls-peer-revocation-checking-and-ocsp-stapling-across-terminating-and-originating-surfaces.md).
  (vault BACKLOG #2169)
