- **A CRL expiry alert about a CA-file CRL no longer claims more than the engine proved.** When a
  hop's CA file now holds a CRL whose signature the engine could not confirm, the alert's `detail`
  asks for a check before restarting. It used to say that every handshake would fail, which a
  start says only of a signature it proves bad. Handshakes can still pass in the unconfirmed case.
  For a proven bad CRL, `detail` now also says it may be removed where a good CRL from that issuer
  is already in the file. For a file one hop loads as its CRL setting and another as its CA file,
  a CA-file fix no longer drops a refused reload's remedy and reason: `detail` gives them after
  the fix, which comes first. The certificate monitor also keeps a CRL row's alert when the scan
  cannot work out which other rows share its file, and logs that as an error.
  (`BACKLOG #3512`)
