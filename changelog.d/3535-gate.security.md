- **A load judges its config directory by listing it, so a share lost after a reload's target check
  is no longer called missing.** The load's own directory check, and `validate_config`, which
  `messagefoundry check` runs, asked `Path.is_dir`, which answers `False` for a share Windows cannot
  reach as it does for a parent the service account cannot traverse. The load's check then dropped a
  fault the read had recorded. Now a load refuses such a directory with `could not read .`, a strict
  read raises the fault, and `validate_config` reports a read that failed, not a missing directory.
  So a share lost after the target check refuses a released reload as `digest_unavailable` and any
  other reload as `unreadable` (vault `BACKLOG #5248`), where each answered `not_found`. At least a directory that is
  absent, or a file in its place, still answers `config directory not found`. So does a drive letter
  this process does not have, even where it is mapped in another session. A directory that lists
  while `Path.is_dir` says no is refused too, since the trust check vets nothing there. A load
  whose trust check cannot list a folder is refused the same way, where a reload answered 500.
  (vault `BACKLOG #3535`)
