- **A key-service outage during a claim no longer dead-letters the row or raises a false
  integrity alert.** On a `vault_transit` store, a queue payload that could not be opened because
  Vault gave no verdict (unreachable, a 5xx, a refused token) was read as the row failing its queue
  tag: the claim dead-lettered a healthy message and wrote an `integrity_drift` alert and audit row.
  Now that failure, a failed read of the store on SQLite, and a dead-letter write that fails are
  treated as infrastructure faults. Under the default pooled claimers the row takes the existing
  infra-fault path, which retries it with backoff and, if the fault lasts, stops the lane with a
  `connection_stopped` alert (`infra_fault_policy = "stop"`) or raises `lane_stuck`
  (`retry_forever`). Under `claim_mode = "per_lane"` the row, and every later row of its lane, goes
  back to `pending` five seconds ahead and is retried with no cap. A tag failure whose dead-letter
  write fails is still audited and alerted. A refusal Vault did give a verdict on is dead-lettered
  and reported as before. (`BACKLOG #5765`, `BACKLOG #5735`)
