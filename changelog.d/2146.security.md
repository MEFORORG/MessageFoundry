- **Signing in again ends the replaced session even when a step-up races it (ASVS 7.2.4).** The
  login supersession used to read the presented session and then revoke it by token hash, with an
  await between. On a first deployment, a step-up that rotated the same session in that gap would
  have left the session live under its new token. The read and the revoke are now one store
  statement, `supersede_session`, on SQLite, Postgres and SQL Server, so the store orders it against
  the rotation: a later rotation fails closed. One limit is stated in
  [SECURITY.md](../docs/SECURITY.md): a rotation that finished before the supersession ran still
  leaves the session live under its new token. (`BACKLOG #2146`)
