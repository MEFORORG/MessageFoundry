- **Signing in again ends the replaced session even when a step-up races it (ASVS 7.2.4).** The
  login supersession used to read the presented session, then revoke it by token hash. On a first
  deployment, a step-up that gave the same session a new token between those two calls would have
  left it live. The two are now one atomic store operation, `supersede_session`, on SQLite, Postgres
  and SQL Server. A step-up after it now fails closed. One case stays open, and
  [SECURITY.md](../docs/SECURITY.md) states it: a step-up that finishes before the supersession
  runs still leaves the session live under its new token. (`BACKLOG #2146`)
