- **Strict X12 validation moves to pyx12 4.0.1, and some `X12SegmentError.code` values change.**
  The `[x12]` extra now needs pyx12 4.0.1 or later. `code` stays the X12 error code from the code
  list of the ack the pass generates: the 997 AK list for a 004010 last group, also when no ack is
  generated, and the 999 IK list otherwise. Against pyx12 4.0.0, at least these differ:
  - a data element error now also adds a segment-level row with code `8` for its segment;
  - an HL count error reports pyx12's name `SEG_8_hl_count_mismatch` where 4.0.0 gave `HL1`;
  - a not-used element reports `I10` on a 999 pass where 4.0.0 gave `10`. On a 997 pass, where the
    997 has no code for it, it reports pyx12's name `ELE_I10_NOT_USED`, never a 999-only code.
- **`X12ValidationResult.ack_transaction` is `None` for an incomplete ack.** pyx12 catches a failure
  in its ack writer and leaves a fragment with no closing IEA; that fragment is no longer labelled a
  997 or 999.
