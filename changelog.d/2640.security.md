- **A scoped caller now gets 403 for every connection name it cannot reach.** The per-name
  connection routes (`/metadata`, `/test`, `/test-credential`, `/start`, `/stop`, `/restart`)
  used to answer 404 for a name the caller's scope listed but no connection used. A listed
  outbound got an audited 403, so the two answers told such a caller which listed names exist.
  Both now get the same audited 403. Only a caller with no channel scope still gets 404 for an
  unknown name. With the engine not started, `/metadata`, `/test` and `/test-credential` now check
  the scope before they answer 503. **This changes a status code:** a script that read a 404 from
  these routes as "connection removed" sees 403 from a scoped account. (`vault BACKLOG #2640`)
