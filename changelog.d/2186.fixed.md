- **A DR backup, restore-verify and restore count the real snapshot when a staging path holds `#`
  or `?`.** The row counts and `integrity_check` opened the snapshot through a bare `file:` URI,
  which SQLite cuts at a `#` or `?`. With such a character in the store's data directory, the OS
  temp directory or the restore destination's directory, the open dropped `mode=ro` and read an
  empty database it created at the cut path. The backup then recorded no row counts in its
  manifest, and a verify of that archive compared nothing and passed. Both checks now open the
  snapshot read-only through the store's own URI builder, as the full verify's decrypt pass
  already did, and a test refuses any new bare `file:` URI in the engine's packages.
  (`BACKLOG #2186`)
