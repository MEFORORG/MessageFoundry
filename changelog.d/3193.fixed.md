- **A failed approval request write is read back, and the write outlives its caller.** When the
  write that files a held request reports an error, the gate reads the request back by its id. If
  the COMMIT landed and only its reply was lost, the caller gets the same 202 and id, so a retry no
  longer files a second releasable copy. A cancel, such as the request timeout, no longer cancels
  the write itself. On SQL Server a release's status write now reads its outcome from `OUTPUT`
  rather than the row count, and an approval outcome whose result has a key json cannot encode,
  or a circular reference, still settles. [SECURITY.md](../docs/SECURITY.md) no longer lists the
  SQL Server command timeout as a lost-COMMIT case: by a reading of pyodbc, the timeout does not
  bound a COMMIT. (vault `BACKLOG #3193`)
