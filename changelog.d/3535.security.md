- **A Windows share the engine cannot reach is a fault, not a missing folder or file.** Windows
  errors 53 and 67 reach Python as a `FileNotFoundError`, so a config directory, a `codesets/` or
  `environments/` folder, or a module on such a share read as absent. A digest that gates a
  dual-control release would then have gone on without those files. Now a strict read raises, and
  a release is refused as `digest_unavailable`. An ordinary read names the path in
  `unreadable_files`, and a start or reload refuses when that path is one the load reads, a
  `codesets/` folder included. A reload whose target directory is on such a share now answers 422
  `unreadable` where it answered 404 `not_found`. A load that finds the directory gone at its own
  first check still reports it as not found. (vault `BACKLOG #3535`)
