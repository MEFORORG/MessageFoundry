- **A config snapshot treats a Windows share it cannot reach as a fault, not an absent path.**
  Windows errors 53 and 67 reach Python as a `FileNotFoundError`, so a config directory, a
  `codesets/` or `environments/` folder, or a module on such a share read as absent. A digest that
  gates a dual-control release would then have gone on without those files. A strict read now
  raises. An ordinary read records the path in the snapshot's `unreadable`, and the fingerprint
  detail reports that as `unreadable_files`. A start or reload refuses when that path is one the
  load reads, a `codesets/` folder included. A plain `config_fingerprint` call returns only the
  digest, so its caller would not see what was left out, and at least the DR backup bundle takes
  its digest that way. Where the target directory still answers, a folder or file on such a share
  refuses a release as `digest_unavailable`. A reload whose target directory is on such a share
  answers 422 `unreadable` at the target check, where it answered 404 `not_found`. If the share is
  lost after that check, the load's own directory check would still refuse it as `not_found`. At
  least that check and `validate_config` still report a base directory on such a share as absent,
  and a value file read from disk still reads as absent there too. (vault `BACKLOG #3535`)
