- **The generic DATABASE dialect now refuses any `odbc_driver` off its driver allowlist.** The
  generic connection string sends its target as `SERVER` alone, and `[egress].allowed_db` and the
  cleartext-hop guard's on-box test read that host, so a driver that takes its target from another
  keyword, a file-based driver among them, would dial a host neither judged. A free name could also
  be a library path a driver manager loads as given. The shipped code built any name, with a
  WARNING. It also let the hop guard allow such a driver on-box from the host in `server`. Building
  a generic `Database` or `DatabasePoll` connection would now refuse it unless `odbc_driver` names
  psqlODBC, MySQL Connector/ODBC or Microsoft's `ODBC Driver <n> for SQL Server` by a whole
  registered name. No declaration lifts that. The `[egress].allowed_db` check refuses the same
  names. The engine's two driver classifiers, one for the TLS gate and one for the egress port,
  are now one. MariaDB Connector/ODBC, library paths, odbcinst aliases such as RHEL's bare `MySQL`,
  and `ODBC Driver 13.1 for SQL Server` are refused at least. `messagefoundry check`'s advisory
  `generic-db-server` line is replaced by `generic-db-driver`, which lists the hops the build
  refuses or may refuse. See *The generic driver allowlist* in
  [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #5041`)
