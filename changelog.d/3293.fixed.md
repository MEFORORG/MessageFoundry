- **The PHI-read, sign-in and ceremony `429`s no longer send a literal `Retry-After`.** The
  PHI-read `429` carried `10`, and the console's `POST /ui/login`, `/ui/mfa`, `/ui/reauth` and
  `/ui/reauth/webauthn` carried `30`, against a default 60 s window. A client that honoured either
  could have retried inside the window and been refused again. The PHI-read and ceremony `429`s now
  send the caller's own wait from the limiter that refused, in whole seconds, rounded up and never
  below 1, as the admin-write `429` already did; while an all-callers budget is spent they send the
  whole window. The value is a reading, not a reservation. `POST /ui/login` sends the whole sign-in
  window instead, so the unauthenticated surface discloses no per-bucket timing.
  (vault `BACKLOG #3293`)
- **A negative `[auth].admin_write_rate_limit_per_actor` is refused at load.** It used to load,
  and the limiter then admitted one write per window. `0` still turns the count off.
  (vault `BACKLOG #3293`)
