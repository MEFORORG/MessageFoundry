- **The PHI-read, sign-in and ceremony `429`s now say how long to wait.** The PHI-read `429`
  carried a literal `Retry-After: 10`, and the console's `POST /ui/login`, `/ui/mfa`, `/ui/reauth`
  and `/ui/reauth/webauthn` a literal `30`, against a default 60 s window. A client that honoured
  either could have retried inside the window and been refused again. Each now sends the time until
  the caller's next attempt would be admitted, in whole seconds, rounded up and never below 1, as
  the admin-write `429` already did. While an all-callers budget is spent, it sends the whole
  window instead, so the header never reveals another caller's timing. (vault `BACKLOG #3293`)
- **A negative `[auth].admin_write_rate_limit_per_actor` is refused at load.** It used to load,
  and the limiter then admitted one write per window. `0` still turns the count off.
  (vault `BACKLOG #3293`)
