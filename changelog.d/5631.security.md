- **The Direct destination's recipient trust check now refuses more than an untrusted issuer.**
  Construction used to check only that the `recipient_cert` was directly issued by a supplied
  `trust_anchor`. It now also checks both certificates' validity windows, that the issuing anchor
  is a CA and the recipient cert is not, the recipient cert's key usages where present, and that
  the recipient cert names every `recipients` address in its `subjectAltName`, so a cert the same
  CA issued to another subscriber is no longer an encryption target. Validity is read again at
  every send; an expiry there is a permanent configuration fault, which stops the lane and keeps
  the queue under the default `credential_fault_policy`. An expired certificate at construction
  refuses the whole configuration's check, reload and start. What is checked, at least, is in
  [CONNECTIONS.md](../docs/CONNECTIONS.md#direct-project--direct-smime-over-smtp-outbound-send-adr-0085),
  *Recipient trust*. (`BACKLOG #5631`)
