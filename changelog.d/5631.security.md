- **The Direct destination's recipient trust check now refuses more than an untrusted issuer.**
  Construction used to check only that the `recipient_cert` was directly issued by a supplied
  `trust_anchor`. It now also refuses a `recipient_cert` or issuing anchor that has expired or is
  not yet valid; an issuing anchor that is not a CA (`basicConstraints` `CA=true`) or whose
  `keyUsage` lacks `keyCertSign`, with a recipient cert pinned as its own anchor exempt; a
  recipient cert whose `keyUsage` lacks `keyEncipherment` or whose `extendedKeyUsage` lacks
  `emailProtection`, each checked only where present; and a recipient cert that does not name
  every `recipients` entry by an `rfc822Name` or a `dNSName` for its domain, so a cert the same CA
  issued to another subscriber is no longer an encryption target. A cert with no
  `subjectAltName` is refused. Validity is checked again at every send: an expiry there is a
  permanent configuration fault that stops the lane and keeps the queue under the default
  `credential_fault_policy`. Refusals name the setting and the property, never a subject or a
  `subjectAltName` value. See [CONNECTIONS.md](../docs/CONNECTIONS.md#direct-project--direct-smime-over-smtp-outbound-send-adr-0085).
  (`BACKLOG #5631`)
