- **The tee says when no site prefix loaded.** `python -m tee anonymize-captures` now prints a
  warning on stderr when no site-code prefix loaded, whatever the cause: no token file at the one
  path, a file that cannot be read, a `MEFOR_FORBIDDEN_TOKENS` value that names no file, or a
  source with no two-digit entry under `[site_prefix]`. The site-code scrub matches nothing then.
  It is a warning, not a refusal: a token-less build loads none. The new `site_prefixes_loaded()`
  in both `surrogates.py` copies reads the state. (`BACKLOG #3516`)
