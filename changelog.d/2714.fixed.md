- **The auth rate limiter drops a key's aged bucket even when that key never returns.** Before this
  fix, `SlidingWindowRateLimiter` removed a key's bucket only inside a later call for the same key.
  A limiter keyed on a client or peer address would have kept one bucket for every address it ever
  saw, for the life of the process. Now the table is ordered by each key's newest hit, and every
  call drops buckets from the front until it reaches one with a hit still in the window. After each
  call the table holds only keys with a hit in the window, at constant work per call on average. A
  key that is still being refused keeps its bucket, so `Retry-After` is unchanged.
  (`BACKLOG #2714`)
