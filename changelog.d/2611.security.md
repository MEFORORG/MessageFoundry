- **`create_managed_app` denies by default.** The managed app factory treated a missing
  `auth_settings` as a request for the open mode, so an embedder that passed nothing would build an
  API whose protected routes answer as the built-in system identity. It now refuses every protected
  route with `503` unless the caller passes `allow_no_auth=True`, the same opt-in `create_app`
  takes. Disabled `auth_settings` alone no longer select the open mode, and the opt-in beside
  enabled `auth_settings` raises `ValueError`. `serve` passes the opt-in itself when
  `[security].require_sign_in = false`. An embedder or a test that relied on the old default adds
  `allow_no_auth=True`. See the enforcement model in [SECURITY.md](../docs/SECURITY.md).
  ([BACKLOG #2611](../docs/BACKLOG.md))
- **A production-tier instance refuses `[security].require_sign_in = false` under `enforce`, on any
  bind.** `serve` refused sign-in off only on an exposed instance, so it would start on a loopback
  bind in every environment. A loopback bind keeps the network out, not the other accounts and processes
  on the host. `serve` now exits 2 when the instance is on the production tier (`prod`, or a name
  with `[security].production_instance = true`) and `[security].enforcement = enforce`. `dev`,
  `staging` and `enforcement = warn` keep the mode on a bare loopback bind. On a production
  instance, set `require_sign_in = true` and run `messagefoundry provision-admin`.
  ([BACKLOG #2611](../docs/BACKLOG.md))
