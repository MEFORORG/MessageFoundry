- **A SOAP fault's Sender or Receiver class is read only from its code element.** The code is now
  the Fault's first child, a comment, CDATA section or processing instruction before it stepped
  over whole: SOAP 1.1's `faultcode`, or SOAP 1.2's `Code` and the `Value` that is the Code's own
  first child. The shipped code took the Fault's first `Value` ahead of any `faultcode`, so a
  `Value` in a Subcode, Role, Node, Reason or Detail that came before the Code's own Value, or one
  ahead of a SOAP 1.1 `faultcode`, decided the class instead; on a first deployment that could have
  made a Sender fault read as a Receiver one and retry until the attempt limit. A Fault whose first
  child is neither, including a SOAP 1.1 Fault whose `faultcode` is not first, now reads as a
  permanent fault, as one with no code always did; it is never read as delivered. Unchanged: whether
  a Fault counts, and the WS-Security check, which still searches the reply
  from where the Fault search starts, so a WS-Security code in any Fault text still dead-letters it.
  The Fault search, and the Fault and Code close-tag searches, step over terminated comments, CDATA
  sections and processing instructions too, so a Fault start tag, or a `</Fault>` or `</Code>`,
  inside such markup no longer decides the class; the Fault search reads the reply from its start,
  so this holds even where the Body start tag sits in that markup. Where every Fault start tag after
  the Body start tag is inside such markup, the first of them is still read as the Fault, as in the
  shipped code; with none after it, the first before it outside such markup is read, else the
  first before it. So such a reply never newly reads as delivered.
  Unchanged: a `</` inside a comment within the `faultcode` or `Value` itself still ends the code
  text, as in the shipped code. At least two shapes with a real Receiver or Server code, which the
  shipped code retried, now read as a permanent fault and dead-letter: a SOAP 1.1
  Fault whose `faultcode` is not its first child, and a `<!` that opens neither a comment nor CDATA,
  such as a DOCTYPE, ahead of the code element.
