- **A mistyped `MEFOR_<SECTION>_<KEY>` variable now refuses the load.** When the section is real
  and the key is not, `load_settings` raises, naming the variable and the nearest real one, never
  its value. It used to be dropped, so `MEFOR_STORE_REQUIRE_ENCRYPTON=true` started an instance
  without the hardening it asked for. Variables that are not settings and are read straight from
  the environment (the Vault, Transit, revocation-attestation and phase-timing names) are spared
  by an explicit list. **Still dropped in silence:** a variable whose section part matches no
  known section. See [CONFIGURATION.md](../docs/CONFIGURATION.md). (`vault BACKLOG #2600`)
- **Four `[auth]` switches are now reported loosenings when `false`:** `require_action_step_up`,
  `password_check_breached`, `password_check_context` and `password_check_username`. Each ships
  `true`, and nothing refuses one. The serve-time warning, `messagefoundry security show` and
  `GET /security/posture` name them. See
  [SECURITY-LOOSENING.md](../docs/SECURITY-LOOSENING.md). (`vault BACKLOG #2600`)
