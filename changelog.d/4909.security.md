- **A proxy credential from the environment no longer crosses a verified TLS leg to the proxy.**
  An `http` target sent to a credentialed `https://` proxy from `HTTP_PROXY` or the system proxy
  settings reached the proxy over TLS that fully verified it, with the credential inside, in at
  least two shapes: with no `HTTPS_PROXY` set, and with `NO_PROXY` naming the proxy's own host.
  Each engine opener now refuses that send before it dials, with `ProxyCredentialsRefusedError`
  and fixed text naming the TLS leg. So does a plainly spelled `Proxy-Authorization` header a
  caller set that no connection admitted, on the same leg. A credential-free proxy is still used
  on that leg, and a `proxy_user` credential its connection admitted is unchanged. Measured on
  REST, SOAP, FHIR, DICOMweb, `FhirLookup`, the alert webhook under its escape and the OIDC legs;
  the token endpoints, the AI broker and the OIDC configuration refuse an `http` target before
  any proxy is chosen. (`BACKLOG #4909`)
