- **A cluster convergence reload now writes its own `config_reload` audit row.** It is the row an
  operator reload writes, with actor `system:cluster-convergence` and `initiator`
  `cluster_convergence`. Before, a node that converged on a sibling's reload left no row, so the
  store's newest config baseline could name the graph that node ran before. A restart on the
  converged bytes then raised a false `config_changed`, and a restart that reverted them raised
  nothing. (vault BACKLOG #3076)
- **A clustered node converges on a sibling's reload that lands during its own start.** The node
  read the shared config version only after its first load, so a sibling's bump in between read
  as applied, and the node kept the bytes it loaded before that reload. It now reads the version
  before the first load. If that read fails, the start goes on and reads it later, as before.
  (vault BACKLOG #3076)
