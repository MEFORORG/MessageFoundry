- **The per-name connection routes no longer tell a channel-scoped caller which names exist.**
  `GET /connections/{name}/metadata` and `POST /connections/{name}/test`, `/test-credential`,
  `/start`, `/stop` and `/restart` now give such a caller the same 403, body and
  `auth.channel_denied` audit row for an inbound outside its scope, a shared outbound, and a name
  that exists nowhere. Before, the first three answered 404 for the last, and the control routes
  refused an outbound with its own body, so on a first deployment a scoped user could have listed
  connection names by probing. An unscoped caller still gets 404 for an unknown name. Names are
  still visible elsewhere: `GET /metrics` is not narrowed, and `POST /connections/{name}/flag` has
  no per-channel check (see `docs/SECURITY.md`). ([BACKLOG #2551](../docs/BACKLOG.md))
