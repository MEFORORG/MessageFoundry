- **A channel-scoped caller can no longer tell which connection names exist.**
  `GET /connections/{name}/metadata`, `POST /connections/{name}/test` and
  `POST /connections/{name}/test-credential` now check the caller's channel scope before they look
  the name up. Such a caller gets the same 403, body and `auth.channel_denied` audit row for an
  inbound outside its scope, a shared outbound, and a name that exists nowhere. Before, the last
  answered 404, so on a first deployment a scoped user could have listed the estate's connection
  names by probing. An unscoped caller still gets 404 for an unknown name.
  ([BACKLOG #2551](../docs/BACKLOG.md))
