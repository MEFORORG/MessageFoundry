- A single-node engine under `[security].enforcement=enforce` now refuses an expired store key or an opted-in expired secret before any listener binds, where the refusal used to come after the graph was up. This early check runs only while `enforce_store_key_expiry` is on; otherwise, and on a cluster, the refusal still comes after the graph. A start refused this way saves only first sightings, so a changed secret is dated from the next successful start. (BACKLOG #5615)
