- **`messagefoundry check` reads an instance declared in the environment alone.** With no
  `messagefoundry.toml`, every leg that reads service settings used to skip before reading a
  single `MEFOR_*` variable, so a site configured by environment alone would have passed a gate
  that read nothing. When `MEFOR_AI_ENVIRONMENT` names the instance, the `posture`, `build-check`,
  `reference-backend` and `upstream-hop-ack` legs and the `oidc-auth-params`, `static-credentials`
  and `alert-smtp-tls` advisories now read the settings from the environment, read no stray
  `messagefoundry.toml` from the working directory, and say "settings from environment only" on
  their line. The dry-run preview reads `snapshot_on_send` the same way. Other `MEFOR_*` variables
  alone, such as a store key in a dev shell, keep the bare-directory skip, because `serve` refuses
  to start without an active environment. (vault `BACKLOG #2355`)
