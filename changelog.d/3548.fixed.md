- **A failure logging the held-copy warning no longer costs a CRL row its date.** The certificate
  monitor logs `a running TLS hop still holds a copy of ...` once a pass for each file. That
  bookkeeping ran inside the guard around the held-copy verdict, so a failure in it would have reset
  the verdict: the row would have been judged by the file alone, and a copy inside the warn window
  could have raised no `crl_expiry` alert. The line is now logged after the verdict, under its own
  guard, and a failure there is logged as an error. No failure of this kind is known to happen.
  (`vault BACKLOG #3548`)
