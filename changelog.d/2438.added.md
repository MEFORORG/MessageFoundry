- **The audit trail, a user's security events and the connection event log page past their
  first window.** `GET /audit`, `GET /me/security-events` and `GET /events` take `offset` and
  `before_id` and return `total`, `limit`, `offset` and `before_id` beside their rows. `GET
  /events` now returns a `ConnectionEventList` object rather than a bare list. `before_id` is the
  snapshot a page was read under: pass the first page's value back with each later offset, and
  rows written in between neither repeat across pages nor move the total. Without it, the grant
  row every `GET /audit` writes before it reads would repeat one row on each page. Each total is
  counted under the same filters as its page: the lock rows a reader without `users:manage`
  cannot see are left out of the total too, and a channel-scoped caller's event total counts only
  its own events. An `offset` or `before_id` past a signed 64-bit integer is refused with 422.
  The store's `list_audit`, `list_connection_events` and `security_events_for_user` take `offset`
  and `before_id` on all three backends, `count_audit` takes `limit=None` for an uncapped count,
  and `connection_event_extent` and `count_security_events_for_user` are new. No schema change.
