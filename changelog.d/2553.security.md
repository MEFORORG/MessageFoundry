- **A remote file upload no longer replaces a partner file written at its chosen name after the
  listing.** With `overwrite` off, the default, the upload picks a free name from a listing, stores
  a temp, then renames it. The rename now refuses a name taken since: SFTP publishes with the plain
  `RENAME` instead of `posix-rename`, after an `lstat` check, and FTP lists again on the publishing
  connection. On a refusal the upload moves on to the next free name, a bounded number of times,
  then retries. FTP's check stays non-atomic on a server whose `RNTO` replaces; see the remote file
  section of `docs/CONNECTIONS.md`. `overwrite = true` still replaces.
  ([BACKLOG #2553](../docs/BACKLOG.md))
