- **A Windows sign-in whose name matches several directory entries can now succeed.** The
  engine used to refuse such a sign-in as ambiguous, so anyone able to write a colliding entry
  could lock the account out. Now, when the engine already holds the account's directory row, it
  picks the one entry that holds the name as its `sAMAccountName` and carries that row's stored
  `objectGUID`, and logs the choice at WARNING. With no stored id, two such holders, or the id on
  two entries, the sign-in is still refused. The row is read through its integrity seal, so on a
  keyed store an edited row picks nothing. A keyless store checks no seal, so there a row written
  straight into the table still picks the entry. (`vault BACKLOG #3228`)
