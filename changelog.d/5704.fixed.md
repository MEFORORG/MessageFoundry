- **A reload that runs while a log-write halt waits for the reload lock no longer rebinds a listener
  over internal stages the halt shut down.** The halt marked its inbounds only once it held the
  reload lock, and the rebind gate refused only a marked inbound, so a reload holding the lock
  rebound the listener and the halt, which read its bound list before the lock, left it bound. The
  halt of the router, transform and response stages is now a claim gate, as the delivery tier's
  already was (ADR 0189): it reads the halt latch as well as the per-inbound marks, in the per_lane
  workers' loop top and in the pooled adapters, which hand a gated row back with no attempt spent
  and park the lane. The halt marks every inbound as it latches, before it waits, and the rebind
  gate probes the log whenever the latch is set, so an inbound a reload adds is gated and refused
  too. The halt no longer pauses an internal lane, so it never changes a lane's phase, a STOP or an
  operator hold. A per_lane internal worker now waits at the gate rather than returning, and while
  the gate holds a reload does not respawn one a content STOP ended. If a probe cleared the latch
  while the halt waited, the halt stops nothing: it lifts only its own marks, respawns the delivery
  workers the claim gate returned, rebinds the listeners a log gate refused while it waited, and
  sends one page under the label `<sink>:stood-down`, so the notifier's realert throttle cannot drop
  it. It also stops nothing if the runner stopped while it waited. A raise from the first page or
  from reading the lanes no longer aborts the halt; the read falls back to every bound listener and
  every outbound not already paused. (`BACKLOG #5704`)
