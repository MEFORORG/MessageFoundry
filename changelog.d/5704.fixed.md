- **A reload that runs while a log-write halt waits for the reload lock can no longer rebind a
  listener over the internal stages the halt shuts down.** The halt marked the inbounds it halts
  only once it held the reload lock, and the reload's rebind gate refused only an inbound already
  marked. A reload holding the lock had unbound every listener and was rebinding them, so it would
  have rebound each one, and the halt, which read its bound list before the lock, would have left
  them bound and ACKing into halted lanes. The halt now shuts the internal stages down as it
  latches, before it waits, so the gate refuses those rebinds and no routing or transform runs
  unlogged while it waits. While the latch is set the gate also refuses, and halts, an inbound
  that a reload adds. The halt reads what it stops once it holds the lock, so it no longer turns an
  outbound that reload engine-parked into an operator pause, and a second halt of the same break
  stops and alerts nothing again. A halt that finds the runner fully stopped when it gets the lock
  pauses nothing, so the next start does not come up with delivery paused. Its one page is now
  sent even when an alert sink raises, and is sized from the lanes it read before it waited.
