- **A reload that runs while a log-write halt waits for the reload lock no longer rebinds a listener
  the halt then leaves bound over internal stages it shut down.** The halt marked its inbounds'
  internal stages only once it held the reload lock, and the rebind gate refused only an inbound
  already marked, so a reload holding the lock rebound every listener and the halt, which read its
  bound list before the lock, left them bound. The halt now marks every registry inbound's internal
  stages as it latches, before it waits; this pauses their pooled router, transform and response
  lanes, or wakes their per-lane workers to stop at their loop-top gate, the item already in flight
  still completing, and it makes the rebind gate refuse those inbounds. While the latch is set, the
  gate also probes the log after it binds an inbound that is not marked yet, and on a failed probe
  unbinds and marks it; an inbound a reload adds without binding a listener does not pass this
  gate. Once it holds the lock, the halt stands down, stopping nothing, if a start ran while it
  waited, if the runner is fully stopped, or if a reload or connection restart probed the log and
  cleared the latch. On a cleared latch it also lifts the internal-stage marks it set as it latched.
  A stand-down sends one page under the sink label with `:stood-down` appended, with a stopped
  count of 0. Otherwise the halt stops only the inbounds still bound and the owned outbounds not
  already paused, so it does not turn an outbound a reload engine-parked into an operator pause,
  and a second halt of the same break stops nothing. An inbound the halt counted as bound whose
  rebind the gate refused while it waited gets the per-connection stop alert too. A raise from the
  alert sink on the first page, from reading the lanes for it, or from either internal-stage
  marking, is logged and no longer aborts the halt. The first page is sent before the wait, and
  its count is of the lanes read then. (`BACKLOG #5704`)
