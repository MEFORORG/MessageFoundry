- **A log-write halt that fires during a reload now stops the listeners that reload rebinds.**
  The halt read which inbounds were bound, and which outbounds were running, before it took the
  reload lock. A reload holding the lock had unbound every listener and was about to rebind them,
  so the halt would have left those listeners bound, ACKing into internal stages it then paused,
  and would have missed an outbound that reload added. It now reads both lists once it holds the
  lock, and still reports a lane the racing reload paused because of the same failure. Its page
  still goes out before anything stops. With the lock free it carries the count of what the halt
  stops; when the lock is held for more than half a second the page goes out at once, says the stop
  is pending, and a second page carries the count. An alert sink that raises no longer aborts the
  halt, and a halt whose latch a recovery probe cleared while it waited stops nothing.
  (`BACKLOG #5704`)
