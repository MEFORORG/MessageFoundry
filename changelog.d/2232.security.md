- **The three hop-policy flags must now be real booleans on every authoring path.** They are
  `tls_hop_attested`, `tls_revocation_attested` and `cleartext_accepted`. The engine read them
  with a plain truth test, and the string `"false"` is truthy. A code-first
  `FhirLookup(cleartext_accepted="false", cleartext_reason=...)` loaded, and the lookup's read hop
  would have crossed as an accepted cleartext hop. `tls_revocation_attested="false"` would have
  counted as attested the same way. On an `inbound()` or `outbound()` the same string loaded and
  was refused only later, at `check` or start, with a message about the reason. Now `messagefoundry
  check`, dry-run and reload refuse any non-boolean value for these flags at load, and the error
  names the key. Every settings-driven seam reads the flags through one strict reader.
  `connections.toml` already refused a non-boolean, so it is unchanged.
