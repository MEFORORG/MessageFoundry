- **A fault in the inbound handler on the raw-TCP and X12 listeners is recorded as
  `handler_error`, and a sender that waits for no reply no longer loses the frames behind it.** Both
  listeners caught the fault in their last-resort arm, recorded `framing_error` though the frame had
  been read cleanly, and dropped the connection. A sender that waits for no reply never resends, so
  that would have lost the frame and every frame already sent behind it. Now an HL7 inbound with
  acknowledgements on closes with no reply, as before, so its sender resends. Any other inbound
  retries the handler in place on that frame a bounded number of times, which recovers a store blip
  with nothing lost, and if the fault outlasts the retries it logs at ERROR that the one frame may
  not be recorded and keeps reading the frames behind it. A fault after the commit can leave a copy
  per attempt, which at-least-once delivery allows. An `OSError` raised by the handler is now
  `handler_error` too, not `peer_reset`. (`BACKLOG #5022`)
