- **A fault in the inbound handler on the raw-TCP and X12 listeners is retried, then recorded as
  `handler_error`.** Both listeners caught it in their last-resort arm, recorded `framing_error`
  though the frame had been read cleanly, and dropped the connection, so a sender that waits for no
  reply would have lost the frame with nothing naming the loss. The listener now retries the
  handler in place on that frame a bounded number of times, which recovers a store blip with
  nothing lost and order kept. If it still faults, the connection event is `handler_error`, an
  ERROR log line says the frame may not be recorded and what that costs the sender, and the
  connection closes so nothing more is accepted behind it. An `OSError` raised by the handler is
  now `handler_error` too, not `peer_reset`. (`BACKLOG #5022`)
