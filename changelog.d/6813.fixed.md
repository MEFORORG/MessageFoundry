- **The sandbox worker releases the failed call before it builds an out-of-memory reply, and a
  torn reply frame is not followed by another.** A worker that ran out of memory built its
  `memory` reply while still holding the raw request frame and the decoded request, and formatted
  the error while the traceback still held the Handler's frames, so the reply could fail and the
  parent read a crash instead. It now clears the error's traceback and chain, drops the frame and
  the request, and collects cycles first. Memory the call left in a global, a cache or a thread is
  not freed, so the reply can still fail there. A reply write that failed with `OSError` was
  followed by a second, error frame, which could land after a partly written one; the worker now
  logs the failure and exits, so the parent fails the message and starts a fresh worker.
  (`BACKLOG #6813`)
