- **The sandbox worker's out-of-memory reply no longer competes with the call it answers, and a
  torn reply frame is not followed by another.** A worker that ran out of memory built its
  `memory` reply while still holding the raw request frame and the decoded request, and formatted
  the error while the traceback still held the Handler's frames, so the reply could fail and the
  parent read a crash instead. A reply write that failed with `OSError` was followed by a second,
  error frame, which could land after a partly written one. The worker now lets go of those first,
  and exits on such a write failure so the parent fails the message and starts a fresh worker.
  (`BACKLOG #6813`)
