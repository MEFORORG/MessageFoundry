- **The remote-debugging guard goes in earlier, covers every command, and logs any file name.**
  The engine refuses a script injected through Python's remote debugging (PEP 768,
  `sys.remote_exec`). `serve` and `supervise` used to install the hook as their first step. Every
  `messagefoundry` command now installs it as it starts, before it parses its arguments. So
  `rotate-key`, `backup`, `restore` and the rest are covered, and the start-up window in which an
  injected script still runs is shorter. **`python -m pdb -p <pid>` can no longer attach to any
  `messagefoundry` command.** Start the command under the debugger instead, as
  `python -m pdb -m messagefoundry <command>`. The refusal's log line now writes the script's file
  name in ASCII, with a backslash escape for every other character. A lone surrogate in that name
  used to fail the write on the `[logging].file` sink and on the syslog forwarder, so the line
  reached neither. The script was refused and counted either way.
  [SECURITY-LOOSENING.md](../docs/SECURITY-LOOSENING.md) says what stays open.
