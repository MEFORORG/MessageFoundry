- **`rotate-key` refuses a configured uploads directory it cannot list.** A configured
  `[store].uploads_dir` that did not exist, such as one on a volume that is not mounted, read as
  zero uploads, so the run printed OK, stamped the key's rotation date and closed the rotation
  record while every upload behind it could still be under the prior key. The command now checks
  the directory before it writes anything, and refuses with exit 2 and nothing changed. A directory
  that goes away during the run fails it as a skipped upload does: PARTIAL, exit 1, no stamp, and
  the rotation record left open. The uploads directory is created on the first upload, so a site
  that set `uploads_dir` and never stored an upload has none either: create it, empty, and re-run.
  An empty directory, or no `uploads_dir` at all, still completes, so an unmounted volume whose
  mount point is itself an empty `uploads_dir` is still not caught. See [PHI.md](../docs/PHI.md).
  (vault `BACKLOG #4940`)
