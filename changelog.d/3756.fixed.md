- **An alert's auto-resolve now retries a failed store write, and logs an ERROR when it gives
  up.** A recovery signal such as `connection_restored` resolves the matching open alert instance
  in a background write. Before, one failed write left the alert open with only a WARNING. Now the
  resolve is tried 4 times, waiting 0.25 s, 0.5 s and 1 s between tries, while it holds that
  alert's write order, so a raise emitted after it still lands after it. If every try fails, an
  ERROR names the alert type and connection, and the alert stays open until the next recovery
  signal. At engine stop, a write still running when the 5 s alert-state drain ends is cancelled
  and logged at ERROR. Not covered: the raise-side write (upsert) is still tried once, the retry
  does not survive a restart, and an emit with no running event loop still drops the write.
  (`BACKLOG #3756`)
