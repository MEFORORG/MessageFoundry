- **An empty body a keyless run left on a keyed store can be delivered.** A keyed open under
  `[store].allow_unmarked_ciphertext` now seals a `pending` empty queue row on a surface that is
  already sealed, with the run's plaintext, so the row is delivered as an empty body instead of
  dead-lettering with an `integrity_drift` alarm. An `inflight` empty row there is not sealed,
  because a peer engine shard may have claimed it and be about to dead-letter it, and on Postgres
  and SQL Server the seal re-checks each row as it writes. So a row a peer claims or dead-letters
  around the seal stays blank and cannot be replayed. Without the opt-out the blank stays refused,
  as before. See
  [SECURITY-LOOSENING.md](../docs/SECURITY-LOOSENING.md). (`BACKLOG #4994`)
