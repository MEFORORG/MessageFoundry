- **A trust anchor's `cadata=` text now keeps the file's bytes where they stand.** It used to drop
  non-ASCII lines and model OpenSSL's PEM reader line by line, and that model did not match what
  `cafile=` reads in every shape, so on a first deployment the text could have trusted a
  certificate that `cafile=` does not show. Now each byte at or above 0x80 becomes `?` where it
  stands, so every line break stays where it is and OpenSSL reads the text in the same pieces as
  the file. On OpenSSL 3.5 and later a UTF-8 byte-order mark is dropped only where OpenSSL's own
  reader drops one; on an older OpenSSL a file where one would be dropped in front of a BEGIN
  line refuses, since the rule is measured only on 3.5. At least a non-ASCII byte inside a PEM block refuses, and so does a NUL byte anywhere.
  This changes what the trust-anchor check admits: some files it refused now load, as `cafile=`
  loads them in the shapes measured on OpenSSL 3.5, and some it loaded now refuse. This replaces
  the line model and the byte-order-mark rule the `BACKLOG #3746` entry in this release describes.
  The encryption-header check now reads non-ASCII comment lines too, so a `Proc-Type:` or
  `DEK-Info:` name on one after the first `-----BEGIN ` refuses, as on an ASCII line. That
  replaces the `BACKLOG #2270` entry's statement that a comment line that is not ASCII is dropped
  before the check. [CONFIGURATION.md](../docs/CONFIGURATION.md) states the rules under
  `tls_client_ca_file`. (`BACKLOG #5229`)
