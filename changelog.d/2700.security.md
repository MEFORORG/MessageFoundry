- **The engine process refuses a script injected through Python's remote debugging, and reports
  the setting.** Python 3.14 lets another process run a script inside a running interpreter
  (PEP 768, `sys.remote_exec`). The engine's children already start with that interface off. The
  engine itself starts through a console-script launcher, which cannot pass the option, so on a
  first deployment code running as the service account would have been able to run Python inside
  `serve` or `supervise`. Both now install an audit hook as their first step. The interpreter drops
  an injected script when the hook raises, and the hook logs a WARNING with the script's file name.
  `security_loosenings()`, and so the serve-time warning and `GET /security/posture`, gains two
  entries: `remote_debug_enabled` with the hook in place, and `remote_debug_unguarded` without it.
  **A default start now reports `remote_debug_enabled`.** The hook closes the interpreter's own
  interface, not the ability to write the engine's memory, so the entry is a residual. To clear it,
  start the engine as `python -P -X disable-remote-debug -m messagefoundry serve ...`. The engine
  does not refuse to start with the interface on, and the installed service and the container
  image do not turn it off yet. `security_loosenings()` takes a new required `remote_debug`
  argument. See [SECURITY-LOOSENING.md](../docs/SECURITY-LOOSENING.md). (`BACKLOG #2700`)
