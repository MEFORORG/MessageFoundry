- **A 2xx reply with a body over the byte bound is no longer sent again.** On the REST, SOAP, FHIR
  and DICOMweb destinations an over-size reply body raised a retryable error even after a 2xx, so
  on first deployment each retry would have re-sent a request the partner had already accepted,
  and the message would then have dead-lettered although it was delivered. The request is now
  sent once. Where nothing needs the body (REST with `capture_response` off, FHIR with it off)
  the message is recorded delivered, the body is dropped, and a WARNING names the connection.
  Where the engine needs the body or passes it on (SOAP, DICOMweb, REST with `capture_response`
  on) the delivery is a permanent refusal with the new code `reply-too-large`, so the message
  dead-letters once. FHIR with `capture_response` on is unchanged and still retries. The table
  is in the REST section of [CONNECTIONS.md](../docs/CONNECTIONS.md). (`BACKLOG #2180`, owner
  ruling 2026-10-05)
