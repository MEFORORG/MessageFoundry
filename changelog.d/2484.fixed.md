- **A TLS list the linked OpenSSL refuses is now a named configuration refusal.** The engine sets
  its own TLS 1.2 suite list on every context it builds and, where the interpreter allows it
  (Python 3.15), its TLS 1.3 suite list and signature scheme list too. On an OpenSSL build that
  refuses one of them, the TLS 1.2 half raised `ssl.SSLError` and the other two `RuntimeError`, and
  only the LDAPS and Vault seam caught them. `narrow_to_approved_suites` and
  `apply_operator_tls_ciphers` now raise `EngineTlsListRefused`, a `ValueError` naming the list and
  `ssl.OPENSSL_VERSION`. On an MLLP or DICOM hop the message names the connector, and it never says
  the connection's `tls_ciphers` was rejected. One gap remains: an opener the REST module builds at
  import would fail the import on such a build, before any seam can report it. OpenSSL 3.5.7
  accepts all three lists. (`BACKLOG #2484`)
