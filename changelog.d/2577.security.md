- **A generic-ODBC `DATABASE` connection takes its connection target from `server` alone.**
  `[egress].allowed_db` is checked against the `server` setting. On `dialect="generic"`,
  `odbc_params` took any driver keyword except `DRIVER`, `SERVER` and `DATABASE`, so a keyword
  could have told the driver to connect somewhere other than the host the allowlist checked.
  `odbc_params` now takes a fixed list of keywords: a port, TLS modes and files, and session
  options. Any other keyword is refused when the connection is built, and the error names the
  keyword and the connection. `odbc_user_key` and `odbc_password_key` take a credential keyword
  only. An `odbc_params` value that holds `;`, `{`, `}` or a control character is refused too.
  This covers the `Database(...)` destination and the `DatabasePoll(...)` source. The SQL Server
  preset never read `odbc_params` and is unchanged. **Breaking for a generic connection that set
  another keyword:** a driver that takes its target under its own keyword, such as Oracle's `DBQ`,
  and psqlODBC's `pqopt`, are refused. See *Accepted `odbc_params` keywords* in
  [CONNECTIONS.md](../docs/CONNECTIONS.md). (vault `BACKLOG #2577`)
