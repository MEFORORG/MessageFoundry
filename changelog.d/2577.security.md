- **On the generic ODBC dialect, no `odbc_params` keyword can give the driver another host.**
  `[egress].allowed_db` is checked against the `DATABASE` connector's `server` setting. On
  `dialect="generic"`, `odbc_params` took any driver keyword except `DRIVER`, `SERVER` and
  `DATABASE`, so a keyword could have told the driver to connect to a host the allowlist never
  checked. `odbc_params` now takes a fixed list of keywords: a port, TLS modes and files, and
  session options. Any other keyword is refused when the connection is built, and the error
  names the keyword and the connection. A keyword given twice is refused. `odbc_user_key` and
  `odbc_password_key` take a credential keyword only. A file keyword must name a path on this
  machine. A value holding `;`, `{`, `}`, a control character or a look-alike of one is refused
  in `odbc_driver`, `database`, `username` and every `odbc_params` value; a `password` may hold
  `;` or `{` but not `}`. This covers the `Database(...)` destination and the
  `DatabasePoll(...)` source. The SQL Server preset never read `odbc_params` and is unchanged.
  **Breaking for a generic connection that set another keyword:** a driver that takes its
  target under its own keyword, such as Oracle's `DBQ`, psqlODBC's `pqopt`, and
  `TrustServerCertificate` are refused. See *Accepted `odbc_params` keywords* in
  [CONNECTIONS.md](../docs/CONNECTIONS.md). (vault `BACKLOG #2577`)
