- **A codec error no longer puts the character or byte it failed on into a log line or a refusal.**
  `str(UnicodeEncodeError)` names the character a codec could not encode, and
  `str(UnicodeDecodeError)` the byte it could not decode. Both are message content. Three paths
  still rendered that text after `safe_exc` stopped doing so: the traceback of any `exc_info` log
  call, a `%s` or `%r` log argument holding the error, and a refusal built as `f"...{exc}"`. On a
  first deployment each would have written one character or byte of a message to the general log.
  The log filter chain, including the tray's, now prints a Unicode error in a traceback (chained
  causes and exception groups included), in a log argument and as a log message from its class,
  codec and position.
  Eleven refusals across the file readers, the sandbox codec, the ingress charset guard and the
  CLI now render it through `safe_exc`, so their text changes from `'utf-8' codec can't decode byte
  0xfe in position 2` to `UnicodeDecodeError: 'utf-8' codec cannot decode at position 2: invalid
  start byte`. A source scan in `tests/test_unicode_error_log_paths.py` fails when a handler that
  catches a Unicode error renders it raw. (vault `BACKLOG #3185`)
