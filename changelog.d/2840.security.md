- **A DR activation reloads the directory the running graph came from.** `POST /dr/activate`
  reloads the graph under the DR run-profile. It used to reload the startup `--config` dir. On a
  first DR deployment, an activation after an operator reload from another allowed root would have
  put the older graph back, and nothing would have said so. It now reloads the directory of the
  last applied reload, else the startup dir, the same one `GET /config/provenance` checks. The
  cluster convergence reload still reads each node's own startup dir. (vault BACKLOG #2840)
- **The DR seed marker's config digest comes from the shared fingerprint rule, at activation.**
  The coordinator behind `POST /dr/activate` and `/dr/release` used to take that digest when it was
  first built, on the event loop, and it caught only `OSError`. A config file name that cannot be
  encoded as UTF-8 would have made the first activate or release fail. The digest is now taken off
  the event loop when an activation writes its `dr_seed` row, over the directory that activation
  reloads. Where the shared rule takes no digest, the marker records none and the activation goes
  on. (vault BACKLOG #2839)
