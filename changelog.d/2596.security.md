- **A released config reload loads only the config its approval named.** When dual control holds
  `POST /config/reload`, the hold's params carry `fingerprint`, the content digest of the target
  directory taken at request time, and the release checks the directory against it before and
  after the load. A release whose config changed answers **422** and audits
  `config_reload_failed` with reason `digest_mismatch`; a hold that carries no digest gives reason
  `no_approved_digest`; a digest the engine cannot take gives reason `digest_unavailable`. A
  request whose digest cannot be taken files no hold and is refused the same way. A reload target
  the engine cannot resolve or list, inline or held, now answers **422** with reason `unreadable`,
  where it used to answer 404 `not_found`, 422 `invalid_config` for a listing that read as empty,
  or a 500 with no audit row. A missing directory, and a
  name no directory can have, still answer 404 `not_found`. See
  [SECURITY.md](../docs/SECURITY.md). (`BACKLOG #2596`)
