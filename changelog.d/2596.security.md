- **A config load reads the directory once and runs only the bytes it read.** Each start and
  reload reads its config into one snapshot after the config source's trust check, and the loader
  compiles every module and helper from it, so no `__pycache__` file runs. A released reload
  checks its approval's digest against that same snapshot before any module runs, so an edit made
  while it loads is neither run nor recorded, and the second digest check after the load is gone.
  See [SECURITY.md](../docs/SECURITY.md). (vault `BACKLOG #2596`)
- **BREAKING: an unreadable `_` helper refuses a start or reload, even when no module imports
  it.** Every file the load reads must be readable; only an unreadable `environments/` value file
  is left out. (vault `BACKLOG #2596`)
- **A release that also loosens the config's permissions is audited as `invalid_config`.** The
  trust check runs before the digest check, so such a tamper is refused there, not as
  `digest_mismatch`. A release refused before the digest check now writes a
  `config_reload_failed` row carrying `approved_fingerprint` and `approval_digest_check` set to
  `not_reached`. (vault `BACKLOG #2596`)
