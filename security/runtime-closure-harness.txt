# The HARNESS runtime closure: every distribution an engine install with the `harness` extra carries,
# transitive dependencies included, with NO other extra and NO development toolchain. Installing the
# harness wheel (packaging/messagefoundry-harness) brings in these names, because that wheel's only
# dependency is `messagefoundry[harness]`. The versions are the lock's; an install resolved from an
# index can take newer ones, and a few names (sspilib, uvloop) apply to one platform only.
#
# This file is the denominator for the `harness` section of docs/RISKY-COMPONENTS.md. It is the core
# closure in security/runtime-closure-core.txt plus what the extra adds, and the page classifies only
# those additions; the core closure's own names are classified above them.
#
# Each line below is a copy of a pin line in security/locks/requirements-harness.lock. That file is
# `uv export --no-emit-project --no-dev --extra harness` of uv.lock, and the DEP-1 gate in
# security.yml fails when it differs from a fresh export. Unlike the two docker/locks files, no image
# installs from it; it exists to be this file's source. Lines are name==version, lowercase and
# sorted, with markers and hashes dropped. tests/test_risky_component_designation.py holds this copy
# to that lock in every name and version. A version edited here by hand changes nothing that
# installs, and the test refuses it.
#
# The harness also imports at least paramiko, pydicom, pynetdicom, openpyxl, pyodbc and asyncpg
# lazily. None is a dependency of the harness wheel, so none is here.
#
