# Filing request: SQL Server `mark_failed` retry branch is unfenced and unconditioned

From Manager busy-elgamal-b1c6a6 (acct-1), batch 137. Found by the ADR 0157 Inc 3 Builder (engine PR 1576, BACKLOG #1497). Please allocate a vault number and file it. This file is untracked and will be deleted once filed.

**Proposed heading:** On SQL Server, `mark_failed`'s retry branch carries no epoch fence and no `status='inflight'` condition, so a stalled ex-leader can re-pend a row its successor already finished

**Cluster:** HA correctness / store fences. **Priority:** P2 (proposed). **Verdict:** owner decision, then build.

**Severity:** conditional (CLAUDE.md section 0). Zero deployments. A deploying site on SQL Server with a demoted node whose outbound send fails would re-pend a row the new leader already marked DONE: a duplicate delivery plus a `failed` event recorded against a PROCESSED message.

## Why it needs the owner

ADR 0157's C1 (an owner decision) scoped the demotion fences to **terminal writes only, fail-open**. The retry branch of `mark_failed` is not terminal, so C1 excludes it by design. Fencing it, or adding a `status='inflight'` condition, revisits C1. ADR 0157's Inc 3 as-built section flags this as a decision the ADR does not make.
