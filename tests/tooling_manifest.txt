# Repo-HARNESS test tier -- the partition behind ci.yml's `tooling` job.
#
# These tests' SUBJECT is the development harness (worktree gate, coordination claims, session mail,
# ledger, announce, the CI workflows themselves), not the MessageFoundry engine. They are 17 percent
# of the suite's tests and 66 percent of its wall-clock time, because each spawns real pwsh/git
# children (~1.0s per test against 0.10s for an engine test). An engine-only PR cannot change their
# result, so running them on the engine legs buys nothing and dominates the critical path.
#
# WHY A MANIFEST AND NOT A DIRECTORY. Moving these into tests/tooling/ was tried and reverted: the
# files are coupled to their location in at least five ways (parents[N] anchors, .parent.parent
# anchors, cross-test imports like `from tests.test_worktree_gate`, references from scripts/ and
# docs/, and relative literals), and two of those classes only surfaced by running the suite. A
# manifest is the same explicit reviewed list without moving anything.
#
# WHY NOT A FILENAME PATTERN. Three separate regex classifiers were tried and each got a different
# obvious case wrong -- CLAUDE.md section 11 records the same failure for the backlog glyph parser.
# Membership is a judgment, so it is written down rather than inferred.
#
# THE RULE FOR A NEW ENTRY: when ambiguous, LEAVE IT OFF. A test that reads real engine source stays
# on the engine leg; wrongly listing one means it stops running on the PRs it guards. Mirrors ci.yml's
# own docs-only filter: "when in doubt a path is CODE".
#
# tests/test_tooling_partition.py pins this file against the tree and fails if a new non-engine test
# lands in neither this list nor its explicit stay-list.
