# Filing request: SQL Server `reset_stale_inflight` returns a negative count under NOCOUNT, and nothing has measured whether NOCOUNT can persist on a pooled connection

From Manager busy-elgamal-b1c6a6 (acct-1), batch 137. Found by the ADR 0157 Inc 3 Builder while repairing engine PR 1576 (BACKLOG #1497). Please allocate a vault number and file it. This file is untracked and will be deleted once filed.

**Proposed heading:** SQL Server `reset_stale_inflight` sums DB-API `-1` rowcounts into a negative "recovered" count when NOCOUNT is on, and whether NOCOUNT can survive onto a pooled connection is unmeasured

**Cluster:** HA correctness / store. **Priority:** P3 (proposed; P2 if the probe finds NOCOUNT can persist). **Verdict:** research first (the probe), then build.

**Severity:** conditional (CLAUDE.md section 0). Zero deployments. Only bites if a session carries NOCOUNT, which production is believed, by reading, not to do.

## Evidence

- CI on engine PR 1576 head `fdbef810e`, jobs 108383797089 (SQL Server 2022) and 108383797148 (2025): `reset_stale_inflight()` returned **-4** (four stage UPDATEs at -1 each) on a freshly opened store whose own test never set NOCOUNT. Earlier tests in the same process had left NOCOUNT on; the suspected route is ODBC driver-manager connection reuse carrying session options. **Not measured.**
- `messagefoundry/store/sqlserver.py`, `reset_stale_inflight`: `recovered += cur.rowcount` per stage, no clamp.
- Callers act on the value: `pipeline/wiring_runner.py` `_recover_stopped_worker_residue` does `if recovered:` (-4 is truthy) and would log "re-pended -4 row(s)"; `pipeline/engine.py` logs it at sharded startup.

## Wider exposure if the probe says NOCOUNT can persist

Every rowcount-gated write on SQL Server, including `resend_to`'s exactly-once gate. `test_resend_plain_parity_ss` (green on both legs) needs rowcount to read exactly 0 right after the applock on the same cursor, which is weak evidence production does not leak it.

## Suggested work

1. A gated probe: set NOCOUNT on a pooled connection via the store's normal paths, return it, borrow again, read `@@OPTIONS & 512`.
2. Stop `reset_stale_inflight` returning negative counts: clamp `-1`, or count through `OUTPUT` as ADR 0157 Inc 3 now does for fenced resolves.
